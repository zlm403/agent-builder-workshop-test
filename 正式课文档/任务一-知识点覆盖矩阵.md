# 任务一 · 知识点覆盖矩阵（隐藏线）

> **用途**：任务一表面是做接金币游戏，实际隐藏线是把 32 个知识点喂给学生。本矩阵把教案每个阶段 ↔ 对应知识点 ↔ 学生要练的动作 ↔ 系统怎么看出"练到了"，让老师知道"教到没、练到没、学会没"。
> **配套**：《任务一教案-接金币游戏.md》（课堂动作）、《正式课知识点分类表.md》（32个知识点定义）、《判断skill知识库.md》（判断信号）。
> **对应关系**：任务一 = 项目一（接金币游戏）。

---

## 一、任务一覆盖的知识点（32 个中本任务主练）

| 类 | 知识点 | 本任务是否主练 |
|---|---|---|
| ① 沟通指挥 | 给参照 / 先做最小 / 先问再动手 / 一次一小步 / 列表格 / 让AI帮你说清 / 复述确认 / 贴图 | ✅ 主练（8 个全练） |
| ② 项目推进 | 多想方案 / 拆第一步 / 问进度 / 卡住暂停 | ✅ 主练（4 个全练） |
| ③ 工具操作 | 打开运行预览 / 装用Skill / 建用知识库 / 用Agent / 跑起来分享 | 🟡 部分（打开运行预览、跑起来分享） |
| ④ 容错纠错 | 先规划 / AI会错 / 做demo验收 / 把错说清 / 让它改 / 改完再跑 / 重开 | ✅ 主练（重点，7 个全练） |
| ⑤ 安全保障 | 先存一份 / 回退撤回 / 知道操作在哪 / 看不懂别删 | 🟡 部分（先存一份、回退撤回） |
| ⑥ 记忆续接 | 装记忆插件 / AI会记住 / 续接进度 / 控制上下文 | 🟡 部分（续接进度、控制上下文） |

> 任务一主练 ① + ② + ④ 共 19 个核心知识点；③⑤⑥ 各练一部分，为任务二/三打底。

## 二、阶段 × 知识点 × 动作 × 检测（覆盖矩阵）

> "系统检测"列 = 学生端/教师端数据里能看到的信号（water-analyzer 已能算水位，可对照）。

### 阶段一 · 任务引入（0-5分钟）
| 知识点 | 学生练的动作 | 系统怎么看出练到了 |
|---|---|---|
| ④ AI会错很正常 | 看老师演示，知道AI第一次生成不等于完成 | 暂无（观察） |
| ① 先问再动手 | 理解"让AI先复述再开工" | 暂无（铺垫） |

### 阶段二 · 定想法（5-10分钟）
| 知识点 | 学生练的动作 | 系统怎么看出练到了 |
|---|---|---|
| ① 先做最小 | 只定一个玩法，不设计完整故事 | 设计卡只填核心玩法 |
| ① 给参照 | 填"我想参考的画面/游戏" | 任务卡/对话出现"像xxx/参考" |
| ① 让AI帮你说清 | 表达不清时让AI反问 | 对话出现"我表达不清，你反问我" |

### 阶段三 · 复述确认（10-15分钟）
| 知识点 | 学生练的动作 | 系统怎么看出练到了 |
|---|---|---|
| ① 复述确认 | 让AI先复述需求，检查角色/规则/范围 | 对话出现"请先复述你理解的需求" |
| ① 一次一小步 | 明确"第一版只做这些" | 对话出现"第一版只做/先不要" |
| ② 拆第一步 | 让AI列出三个步骤 | 对话出现"列出你准备完成的步骤" |
| ① 列表格 | 需求列成清单 | 对话出现列表式需求 |

### 阶段四 · 制作初版（15-27分钟）
| 知识点 | 学生练的动作 | 系统怎么看出练到了 |
|---|---|---|
| ① 先做最小 | 只做移动/掉落/计分，不加大功能 | 任务卡锁定范围，对话"只完成核心玩法" |
| ③ 打开运行预览 | 找到运行/预览入口 | 作品被打开/运行（track 事件） |
| ② 问进度 | 完成后问"现在到哪了" | 对话出现"现在到哪了/下一步" |
| ④ 先规划 | 按步骤等AI完成再继续 | 对话节奏（无连续乱指令） |

### 阶段五 · 运行验收（27-35分钟）
| 知识点 | 学生练的动作 | 系统怎么看出练到了 |
|---|---|---|
| ④ 做demo验收 | 按验收表逐项测试（能动/掉落/计分） | 作品运行 + 验收表填写 |
| ② 卡住暂停 | 卡住先暂停，不连续乱发指令 | 对话间隔/求助行为 |
| ③ 知道操作在哪 | 用验收表逐项核对 | 操作轨迹 |

### 阶段六 · 第一次纠错（35-43分钟）
| 知识点 | 学生练的动作 | 系统怎么看出练到了 |
|---|---|---|
| ④ 把错说清 | 用"操作/期望/实际"描述问题 | 对话出现三要素句式 |
| ④ 让它改 | 明确"请只修复这个问题" | 对话出现"只修复/不要改其他" |
| ④ 改完再跑 | 修改后重新运行验证 | 修改后再次运行（track） |
| ⑤ 先存一份 | 修改前保存可回退版本 | 保存动作 |
| ⑤ 回退撤回 | AI改坏了会回退 | 回退动作 |

### 阶段七 · 优化+个性化（43-51分钟）
| 知识点 | 学生练的动作 | 系统怎么看出练到了 |
|---|---|---|
| ① 列表格 | 视觉要求列成清单 | 对话出现表格/清单式视觉需求 |
| ① 一次一小步 | 只优化视觉，不碰玩法 | 对话"只优化视觉，不修改规则" |
| ① 复述确认 | 让AI先复述修改内容 | 对话"请先复述你准备修改的内容" |
| ⑥ 控制上下文 | 对话太长时开新会话 | 新会话/进度记录 |

### 阶段八 · 发布互玩（56-60分钟）
| 知识点 | 学生练的动作 | 系统怎么看出练到了 |
|---|---|---|
| ③ 跑起来分享 | 发布作品、交换链接 | 发布/分享动作 |
| ⑤ 先存一份 | 保存可运行版本 | 保存动作 |
| ⑥ 续接进度 | 填写项目进度记录 | 进度记录/让AI读进度继续 |
| ② 拆第一步 | 记录"下次第一步做什么" | 记录 |

## 三、任务一的隐藏线总结

```
表面（学生看到）：做一个接金币小游戏
隐藏线（实际学到）：
  ① 把话说清楚：参照/最小/复述/分步/列表（8个）
  ② 知道下一步：拆步/问进度/暂停（4个）
  ④ 会纠错：AI会错/验收/说错三要素/让它改/改完再跑（7个）
  ⑤ 有退路：先存/回退（2个）
  ③⑥ 打底：运行预览/跑起来分享/续接进度（3个）
```

**任务一结束时，学生应该已经体验过 ①+②+④ 共 19 个核心知识点，每个至少练了 1 次**——游戏做出来了，知识点的"手感"也埋下了。

---

## 四、老师怎么用这张表控制课堂

1. **课前**：对照矩阵，确认每个阶段要带出哪些知识点（不用刻意点名，带动作即可）。
2. **课中**：每个阶段结束，老师看学生行为（对话/操作）判断"这阶段的知识点练到没"——没练到的阶段，多用几分钟补。
3. **课后**：对照矩阵复盘——哪些知识点全班普遍没练到，就是任务二/三要重点补的。
4. **系统配合**：water-analyzer 已能根据行为算学习水位（6类），本矩阵是"哪类知识点该在哪个阶段练"的细化依据。
