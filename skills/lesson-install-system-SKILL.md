# 课程装进监控系统

## 一、技能目标

把一份写好的课堂教案（Markdown），转换成监控系统里能直接上课的形态：

1. 拆成系统的任务列表（老师逐个"设为当前"控制节奏）；
2. 每个任务配「关键步骤 + 核心知识点」（大屏只投关键的，不投全文）；
3. 每个任务生成大屏内容块（可投屏）；
4. 存入课程库（以后一键加载复用）；
5. 生成"知识点覆盖矩阵"（隐藏线：阶段×知识点×动作×检测，验证教到/练到/学会）。

**核心原则：表面是作品制作，隐藏线是知识点覆盖。老师控制节奏，系统验证覆盖。**

---

## 二、装系统前的准备

先确认三份输入齐不齐：

1. **教案**：完整课堂教案（含阶段/教师步骤/学生步骤/AI指令/验收表）。缺则用 `lesson-plan-generator` skill 先生成。
2. **知识点分类**：六大类 32 知识点（《正式课知识点分类表.md》）。
3. **系统状态**：监控服务器在跑（`python server.py 8099`）。

---

## 三、执行步骤

### 第 1 步：确定任务拆解粒度

教案的"阶段" ≠ 系统的"任务"。系统任务按"学生做的一个完整步骤块"拆，一般 4-7 个。

参考（任务一接金币游戏拆成 7 个）：
- 任务一 定想法 → 任务二 复述确认 → 任务三 制作初版 → 任务四 运行验收 → 任务五 第一次纠错 → 任务六 优化+个性化 → 任务七 发布互玩

拆解规则：
- 每个任务学生做一件"能验收的事"；
- 老师逐个"设为当前"控制节奏（学生只看到当前任务，防跑偏）；
- 时间不足可合并（如"优化+个性化"合并为一个）。

### 第 2 步：写每个任务的内容

每个任务含四个字段：

```
no:      任务一 / 任务二 ...
title:   一句话（定想法 / 复述确认 ...）
steps:   关键步骤（3-4 条，大屏/学生端显示，只放关键的，不放大段教案）
points:  核心知识点（★ 开头，每条一个知识点/注意点）
```

规则：
- **大屏只投关键**：steps/points 精炼，不放全文、不放大段话术；
- 知识点从教案该阶段的动作里提取（对应六大类）；
- 学生端任务看板显示同一份 steps/points。

### 第 3 步：存进课程库 + 载入当前课程

```
POST /api/library/save   { name:"接金币游戏课", tasks:[...] }   → 存档复用
POST /api/library/load   { name:"接金币游戏课" }                 → 设为当前课程
```

### 第 4 步：生成大屏内容块

每个任务一个可投块（自动任务块，id `blk_task_<任务>`）：

```
POST /api/screen/save {
  id: "blk_task_task一", type: "task",
  title: "任务一 · 定想法",
  content: { title, steps, points },
  source: "auto"
}
```

老师上课时在大屏内容控制台点哪个，大屏投哪个。

### 第 5 步：生成知识点覆盖矩阵（隐藏线）

对照六大类 32 知识点，做矩阵：

```
阶段 × 知识点 × 学生动作 × 系统检测信号
```

检测信号 = 学生行为里能看到的动作（water-analyzer 已按行为算学习水位）：
- 复述确认 → 对话出现"请先复述你理解的需求"
- 把错说清 → 对话出现"操作/期望/实际"三要素
- 改完再跑 → 修改后再次运行
- 先存一份 → 保存动作
- 跑起来分享 → 发布/分享动作

矩阵要点：
- 标出本任务主练的类（如任务一主练 ①+②+④ 共 19 个）；
- 每个知识点落到至少一个"学生动作"；
- 老师据此控制：课前看要带哪些、课中看练到没、课后复盘哪些没覆盖。

---

## 四、验证

装完后确认：

1. 教师端课堂任务区显示 7 个任务（可"设为当前"/"一键全部推送"）；
2. 学生端任务看板显示当前任务（未解锁🔒锁定）；
3. 大屏内容控制台列出任务块（点哪个投哪个）；
4. `/api/lesson` 当前课程正确；
5. 课程库里有存档（`/api/library` 能看到）。

---

## 五、配套文档

- 教案：《正式课文档/任务X教案-xxx.md》
- 覆盖矩阵：《正式课文档/任务X-知识点覆盖矩阵.md》
- 知识点：《正式课文档/正式课知识点分类表.md》
- 系统：`ar-class-monitor-demo/`（监控服务器 + 三端）

## 六、注意事项

1. **大屏只投关键**：不要把整份教案投上去，只投当前任务的 steps + points。
2. **隐藏线优先**：任务是否"可控"取决于知识点覆盖矩阵，不是任务做得多炫。
3. **老师控制节奏**：学生只看到"设为当前"的任务，防一次拿全部跑偏。
4. **课程库复用**：装好存库，下次上课"加载课程"即用，不重新拆。
5. **上云待办**：课程库最终迁云端（阿里云 OSS），本机先跑通。
