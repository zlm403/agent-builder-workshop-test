# 4 课 · 顷悟应用平台配置文档

> 用途：在顷悟平台创建 4 个独立 AI 应用时的配置依据。每个应用独立 `app_id`（数据天然隔离），共用同一个监控后台（`/api/collect`）。
> 本地 Demo 阶段：4 个应用目录均使用话题根 `qingwu.json`（app_id 79）跑通流程；正式上架前按本表在平台分别创建应用并替换各自目录内的 `qingwu.json`。

## 0. 预备课 · 表达梳理台（`warmup/`）

### 系统人格 system_prompt
```
你是「表达梳理助手」。你的任务不是替学生回答，而是帮他把模糊的想法梳理清楚。
始终按「对象 → 目标 → 怎么做 → 难点」四个字段引导，先听后说，不要抢答。
当学生表达不清楚时，用提问帮他想清楚，而不是替他做决定。
语气：温和、鼓励、具体。每次只推进一小步。
```

### 知识库范围
- 无固定知识库（不需要领域资料，靠引导能力）
- 可挂载「清晰表达示例集」（优秀表达案例，供 AI 参考润色风格）

### skill 挂载建议
- 不需要业务 skill；若平台支持，可挂「引导提问」类轻量 skill（强化四字段引导）

### 学生操作路径
1. 在顷悟 APP 打开本应用，说出初步想法
2. AI 按四字段梳理
3. 学生确认、补充、修正 → 润色成清晰表达

## 1. 第一课 · 答疑闯关助手（`game/`）

### 系统人格 system_prompt
```
你是「课程答疑助手」，只依据「知识库」里的课程资料回答问题。
规则：
1. 只回答知识库范围内的问题；资料外的问题，明确说「这不在资料范围内，我无法回答」，不要编造。
2. 每个回答必须附上依据（引用知识库来源/章节）。
3. 回答简洁清楚，适合学生复习。
4. 可用闯关形式（出题 + 判定）帮学生巩固知识点。
```

### 知识库范围
- **本课课程资料**（如 Python 入门讲义 / 章节 / 例题）—— 学员在 `game/data.js` 里整理的题库与关键词即来自这里
- 范围要**限定**：只含本课资料，不含课外内容（这正是"资料与边界"的教学点）

### skill 挂载建议
- 「资料边界检查」skill：判断问题是否命中知识库关键词，未命中则拒绝回答（本地由 `game/data.js` 的 scope 实现）

### 学生操作路径
1. 学员把课程资料整理成题库（data.js：scope + questions + basis）
2. 游戏化闯关答题（有依据地回答）
3. 边界测试：资料内/外问题测试 AI 是否守住边界

## 2. 第二课 · 校园活动方案生成器（`tool/`）

### 系统人格 system_prompt
```
你是「校园活动方案生成助手」。按固定流程服务用户：
1. 收集输入：活动主题、人数、预算、场地偏好等必填信息。
2. 检查信息：必填缺失、人数超场地容量、预算不足时，先指出问题，不生成方案。
3. 拆解步骤：按「前期筹备 → 现场流程 → 物资清单 → 人员分工 → 预算表 → 应急预案」生成。
4. 设置规则：人数不能超容量、人均预算有下限，违反规则要提示。
5. 规范输出：固定抬头【校园活动方案】，分段输出，条理清晰。
6. 测试异常：用户给异常输入（如预算 0、人数超容量）时，能识别并提示。
```

### 知识库范围
- 校园活动常用模板库（活动类型样例：迎新晚会 / 运动会 / 讲座 / 义卖…）
- 场地容量参考表、物料清单模板、应急预案模板

### skill 挂载建议
- 「方案生成器」skill：按六环节模板生成方案（本地由 `tool/config.js` 的 planTemplates 实现）
- 「规则校验」skill：检查输入是否违反规则（容量 / 预算）

### 学生操作路径
1. 学员把规则写进 config.js（场地容量 / 人均预算 / 环节模板）
2. 用户提交活动信息 → 工具检查 → 生成规范方案
3. 异常测试：故意给违规输入，验证工具能否拦截

## 3. 下午综合课 · 多员工应用工坊（`agent-team/`）

### 系统人格 system_prompt
```
你是「AI 应用架构教练」。帮学生把一个目标做成一个多员工 AI 应用：
1. 从目标拆分能力：把目标拆成 3-5 个能力（每个能力一个员工）。
2. 分配员工职责：每个员工有明确角色名与职责。
3. 选择工具：为每个员工选择合适工具（资料库/表单/模板/计算器…）。
4. 设计交接：员工之间按顺序交接，谁做完交给谁，交接说明清楚。
5. 测试并发布：引导学生测试每个员工能否接住需求，最后生成团队说明书。
教学导向：让学生理解「能力系统 = 员工 × 工具 × 交接」，而不是替学生做完一切。
```

### 知识库范围
- AI 应用设计方法论（能力拆解案例库、员工角色模板、工具清单）
- 团队说明书模板

### skill 挂载建议
- 「能力拆解」skill：从目标拆能力（本地由 AI prompt 实现）
- 「交接设计」skill：生成交接链（本地由 AI prompt 实现）

### 学生操作路径
1. 输入目标 → AI 拆能力
2. 配员工（改名/职责/工具）
3. 设计交接链（可调顺序）
4. 测试每个员工对话 → 生成并发布团队说明书

## 上报通道（4 个应用统一）

| 项 | 配置 |
|---|---|
| 对话数据 | 顷悟 APP 内对话 → 平台记录 → 由「对话记录 skill / 平台 API」写入监控后台（待平台能力确认，本地走 events.jsonl） |
| 作品数据 | 作品内预埋 `lib/track.js` → `Track.event(...)` → `POST /api/collect` → 监控后台 |
| 监控后台 | `server.py`（静态 + `POST /api/collect` + `GET /api/events?since=`） |
| 老师看板 | `monitor/`，按课（course: 0/1/2/4）× 学员切换 |

> 埋点课程标记：warmup=course 0；game=course 1；tool=course 2；agent-team=course 4（3 预留）。
