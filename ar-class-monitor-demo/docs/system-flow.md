# 整课系统流程说明 · 到底怎么回事

> 版本：v1 · 2026-08-07
> 依据：CodeBuddy 侧「轻物·显影副本 V3 整课流程导览」（flow_v3.html）+ 本仓（ar-class-monitor-demo）落地现状
> 定位：给老大/讲师看的"系统是怎么转的"总说明，与 `demo-script.md`（怎么演示）互补。

---

## 0. 一句话

**一天 4 课，学生做 4 种 AI 任务（表达 / 答疑游戏 / 方案工具 / 多员工应用）；系统在后台"不显山不漏水"地把两类数据（Agent 对话 + 作品操作）收进同一个事件流；同一份数据三向分流——学生看自己的镜子、老师看全班的聚合、大屏看匿名的投影；老师看聚合随时推步骤/定向指导，回流到学生端再动。一节课就在转这个环。**

四个角色：

| 角色 | 干什么 | 粒度 |
|---|---|---|
| 🟦 学生端 | 任务看板 + 教学内容区（四课切换）+ 作品运行容器 | 看自己 |
| 🟨 处理服务 | 落库 + 穿透分析 + 三向分流 | 数据中枢 |
| 🟩 教师端 | 全班聚合 + 决策推送（推步骤/定向） | 看全班 |
| 🟪 大屏端 | 匿名班级"隐形壳"投影 | 看整体 |

## 1. 端到端流程（这堂课怎么跑，9 步）

```
①课前准备 → ②推步骤 → ③做任务 → ④自动捕获 → ⑤理解棱镜穿透
   ↑                                                  ↓
⑨验收终图 ← ⑧回流(推回学生看板) ← ⑦师决策 ← ⑥三向分流
```

### ① 课前准备 · 课程装填，四任务与验收线就位
- 老师在教师端配好四堂课：预备课（轻量表达）/ 第一课（游戏创造·资料答疑）/ 第二课（工具·活动方案）/ 下午（AI 应用·多员工）
- 平台先把"骨架"铺好：任务看板、验收探针、维度定义预置
- 数据服务启动（本仓：`python server.py`；轻物侧：`python mock_server.py`）

### ② 推步骤 · 老师点一下，全班同步亮灯
- 老师选当前环节 → 全班推送（或选若干人定向推送）
- 学生任务看板收到新步骤，大屏同步显示「当前步骤」

### ③ 做任务 · 学生做任务，四任务形态不同
| 课 | 形态 | 学生干什么 |
|---|---|---|
| 预备课 | 轻量表达 | 一句话说出想做的 AI 应用 |
| 第一课 | 游戏创造 | 给 AI 喂资料，问资料内/外问题，游戏化看它答得对不对 |
| 第二课 | 工具 | 收集输入 → 检查 → 拆步骤 → 设规则 → 规范输出 → 测异常 |
| 下午 | AI 应用 | 从目标拆能力 → 分员工 → 选工具 → 设计交接 → 测试发布 |

> 关键设计：应用形态（游戏/工具/网页）只是"怎么体现任务"，**对话与操作始终被捕获**——不二选一。

### ④ 自动捕获 · 每轮都被收进口袋，不等学生主动交
- Agent 对话：每轮请求/回复由平台侧 skill 写入事件流（`source='codebuddy'`）
- 作品操作：作品内预埋 `track()` → `POST /api/collect`（`source='work'`）
- 轻物侧还支持网页内模拟对话（`source='web'`）与"粘贴外部对话来显影"（`source='paste'`）
- 捕获是"无感"的：学生只管做任务，老师不用催交

### ⑤ 理解棱镜穿透 · 一核多表，每课穿各自的维度
- 核心机制（学生端镜子 / 教师端热力 / 大屏投影三端共用同一份 `lib/analyze.js`）：
  - **gridFor(task, events)**：把学生在该课留下的作品事件轨迹，按该课自己的维度表拆格、标六色状态（✅已确认 / 📋已识别 / 🟡推测 / △待澄清 / ⬜空缺 / 🔴冲突）
  - **detectGap**：找缺口（推测/待澄清/空缺/冲突），给观察而不是判定
  - **paraphrase / gapText**：用「模型把你的…理解成…」回读（镜子不说教）
- **维度表按课配置，绝不统一套一套格子**：
  | 课 | 棱镜 | 穿什么 |
  |---|---|---|
  | 预备课 | 语言棱镜（10 格） | 对象/场景/问题/任务/目标/标准/范围/互动/限制/输出 —— 想法说清楚没 |
  | 第一课 | 边界棱镜（5 格） | 资料整理/有依据回答/边界测试/测试深度/边界外处理 —— 依据在不在资料边界内 |
  | 第二课 | 规则棱镜（6 格） | 输入收集/信息检查/步骤拆解/规则约束/规范输出/异常测试 —— 流程与规则立没立 |
  | 综合课 | 系统棱镜（5 格） | 目标拆解/员工分工/工具选型/交接设计/测试发布 —— 能力系统成没成 |
- 红线：黄绿不混、镜子不说教、只观察不自动改

### ⑥ 三向分流 · 同一份数据，三端各看各的粒度
- 学生端：③数据穿透看板 = 自己的镜子（原句 / 模型听到 / 缺口 / 重写）
- 教师端：全班维度热力（哪格最弱、谁卡住）
- 大屏端：匿名班级隐形壳（不显示姓名，只显示"8 人对象🟡、5 人场景⬜"）
- **同源不同粒度，互不串味**

### ⑦ 师决策 · 老师看聚合，决定下一推什么
- 聚合面板：全班最弱维度、每位学生最弱格
- 决策权在老师：推哪一步、推全班还是定向，平台只辅助不剥夺

### ⑧ 回流 · 推步骤/定向 → 回到学生看板
- 老师点「全班推送」或「定向推送」→ 写学生任务看板 → 广播大屏
- **闭环合上：学生数据 → 服务穿透 → 老师看见 → 老师推回 → 学生再动**

### ⑨ 验收终图 · 四任务收口，维度成形，数据可回看
- 每课跑固定验收：用一句话说清「给谁/场景/帮什么/怎样算成功」
- 归档：四任务产物 + 全部 turn 入库，可回看每个学生的维度演化
- 终图：四课达标率、最弱格迁移趋势；下节课接着转同一个环

## 2. 四任务承载（四课分别怎么上）

| 课堂阶段 | 表面项目 | 真正教学底层 | 能力升级 | 承载形态 | 主要激活维度 |
|---|---|---|---|---|---|
| 预备课 | 轻量表达任务 | 对象与目标 | 模糊想法 → 清晰表达 | 轻量任务（输入框+一句话回读） | 对象、目标（场景、问题待点亮） |
| 第一课 | 课程资料答疑复习助手 | 资料与边界 | 会回答 → 有依据地回答 | 游戏创造（迷你问答+依据标签） | 资料、边界（承上：对象/目标） |
| 第二课 | 校园活动方案生成器 | 流程与规则 | 回答问题 → 完成服务 | 工具（收集/检查/拆步骤/规则/异常测试） | 流程、规则（承上：资料/边界） |
| 下午综合 | 多员工应用 | 能力与工具 | 单个员工 → 能力系统 | AI 应用（多员工协作面板） | 能力、工具（承上：流程/规则） |

> 教学底层就是老大定的四组维度：对象与目标 / 资料与边界 / 流程与规则 / 能力与工具。每课"承上启下"，维度逐步累积成完整棱镜。

## 3. 数据链路（两路数据，一个事件流）

```
学员/老师 与 AI 对话 ──(平台 skill 记录)──┐
                                          ├─→ events.jsonl ──GET /api/class(聚合)──→ 教师端(热力/分数环) + 大屏端(匿名轮播)
作品页操作 track() ──POST /api/collect───┘        │
                                          └─GET /api/events?since=──→ 学生端(自己的镜子) + 教师端(时间线/穿透)
```

- 统一事件流：所有数据落到同一份 `events.jsonl`，`sid` 标识学员，`course` 标识第几课，`source` 标识来源
- 两路数据：
  1. **对话数据**：顷悟 Agent 每轮对话由对话记录 skill 自动写入（本仓已落地）
  2. **作品数据**：作品内预埋 `track()` 上报（`express_submit / game_start / question_answered / game_over / boundary_test / tool_submit / tool_check / tool_result / tool_error / goal_submit / employee_configured / handoff_designed / published` 等）
- 三端消费同一份数据：
  1. **学生端** `GET /api/events?since=` 过滤自己的事件 → `lib/analyze.js` 显影自己的理解棱镜（含预备课回读句）
  2. **教师端** `GET /api/class` 聚合 → 班级理解棱镜热力 + 每人清晰度分数环/缺口数 + 时间线/穿透分析
  3. **大屏端** `GET /api/class` 聚合 → 班级棱镜自动轮播 + 匿名学生墙（只显示首字，不显示学号姓名）
- 穿透判定统一走 `lib/analyze.js`（一核多表），服务端只做字段聚合，不重复实现判定逻辑

## 4. 已落地 vs 目标态

| 能力 | 本仓（ar-class-monitor-demo） | 轻物侧（CodeBuddy 原型） | 说明 |
|---|---|---|---|
| 4 课作品 | ✅ warmup/game/tool/agent-team | ✅ 四任务切换 | 同课程体系两套实现 |
| 作品埋点 | ✅ track.js → /api/collect | ✅ iframe + track.js | 统一 source='work' |
| Agent 对话捕获 | ✅ 对话记录 skill → events.jsonl | 🔌 接入缝（source='codebuddy'） | 平台开放事件 API 即接通 |
| 学生端工作台 | ✅ student/（任务看板+引导+作品容器） | ✅ 学生端三区（看板/内容/穿透看板） | 轻物侧多"数据穿透看板"（镜子） |
| 教师端聚合 | ✅ monitor/（按课/学员切换+穿透分析） | ✅ 教师端（聚合+推送） | 轻物侧多"推步骤/定向" |
| 大屏匿名投影 | ⬜ 未做（P5 待做） | ✅ bigscreen_app.html | 若要可移植 |
| 理解棱镜穿透 | ✅ lib/analyze.js 一核多表（pre 语言 10 格 / t1 边界 5 格 / t2 规则 6 格 / t3 系统 5 格） | ✅ analyze.js（fillGrid/paraphrase/detectGap） | 轻物侧核心已移植；一核多表 = 每课穿各自维度，不统一套 10 格 |

> 方案取舍（轻物侧记录）：**B 为骨、A 为血**——自写前端+事件流先把课跑起来；等平台对话事件接口打通，把 `source='codebuddy'` 的真实对话接进来，架构不动只换数据来源。本仓与之同构：顷悟 Agent 对话已通过 skill 接通（A 的血已有一部分），作品埋点是 B 的骨。

## 5. 一节课的"转环"（给讲师的一句话总结）

**学生做 → 系统无感捕获 → 穿透成维度 → 三端各看各的 → 老师看聚合 → 老师推一步 → 学生再做。** 四课层层叠维度，一天下来全班的理解棱镜从大片空白被填满——这就是整套系统"到底怎么回事"。
