# 云端系统访问本地视频 · 方案与排查记录

> 目标系统：`aliyun-classroom-v2`（试听课，Next.js + Prisma + PostgreSQL）
> 记录时间：2026-08-23
> 场景：系统跑在阿里云上，浏览器在本地笔记本，希望视频走本地硬盘（快），不走云端（慢）。

---

## 1. 目标

我的系统（试听课）部署在**阿里云**上（`http://8.130.70.114:3000`，Docker 容器 `classroom-v2`，Next.js 14.2.35）。

- 由于**从阿里云访问视频太慢**（视频文件在云端，经公网传输），
- 想改为：**浏览器照常从阿里云打开页面，但视频直接读本地电脑硬盘**，实现秒开。

一句话：**页面在云端，视频在本地；云端不可达时才兜底回云端。**

---

## 2. 现状架构（改造前 vs 改造后）

### 2.1 双源视频机制（项目原有设计）

前端统一用 `SmartVideo` / `VideoSource` 组件加载视频，按以下顺序找源：

```
本地笔记本源（快）  →  云端 /videos/（Next 静态）  →  云端 /api/media/file/（媒体库兜底）
```

- 本地源基址来自运行时配置 `data/video-server.txt`，内容为：`http://192.168.1.13:9123`（本地笔记本 IP + 视频服务端口）。
- 教师端可在「视频服务器地址」处填写，保存后全局生效，无需重新构建。

### 2.2 部署形态（关键）

## 3. 具体操作与代码改动

### 3.1 本地视频服务 `scripts/video-server.js`（改动核心）

作用：纯 Node 零依赖的本地视频服务，支持 Range 分段（拖动不卡）。

**改动 1：新增媒体库路径映射**

原实现只服务 `public/videos/`，媒体库视频（`/api/media/file/xxx.mp4`）请求本地源必 404 → 必然回退云端。改造后同时服务两个目录：

```js
const PORT = 9123;
const VIDEOS_DIR = path.join(__dirname, '..', 'public', 'videos');
const MEDIA_DIR = path.join(__dirname, '..', 'public', 'media');   // 新增
```

```js
// /videos/<文件名>：public/videos/（原有）
if (url.pathname.startsWith('/videos/')) {
  const name = decodeURIComponent(url.pathname.slice('/videos/'.length));
  const file = path.join(VIDEOS_DIR, name);
  if (!file.startsWith(VIDEOS_DIR) || !fs.existsSync(file) || !fs.statSync(file).isFile()) {
    send404(res); return;
  }
  serveFile(res, file, req.headers.range);
  return;
}

// /api/media/file/<文件名>：public/media/（新增，兼容前端 SmartVideo 拼出的本地地址）
if (url.pathname.startsWith('/api/media/file/')) {
  const name = decodeURIComponent(url.pathname.slice('/api/media/file/'.length));
  const file = path.join(MEDIA_DIR, name);
  if (!file.startsWith(MEDIA_DIR) || !fs.existsSync(file) || !fs.statSync(file).isFile()) {
    send404(res); return;
  }
  serveFile(res, file, req.headers.range);
  return;
}
```

**改动 2：抽公共 `serveFile`，统一支持 Range**

```js
function serveFile(res, file, range) {
  const stat = fs.statSync(file);
  const total = stat.size;
  const mime = MIME[path.extname(file).toLowerCase()] || 'application/octet-stream';

  if (range) {
    const m = /bytes=(\d*)-(\d*)/.exec(range);
    const start = m && m[1] ? parseInt(m[1], 10) : 0;
    const reqEnd = m && m[2] ? parseInt(m[2], 10) : total - 1;
    const end = Math.min(reqEnd, total - 1);
    if (start > end || start >= total) {
      res.writeHead(416, { 'Content-Range': `bytes */${total}` });
      res.end(); return;
    }
    res.writeHead(206, {
      'Content-Type': mime,
      'Content-Range': `bytes ${start}-${end}/${total}`,
      'Accept-Ranges': 'bytes',
      'Content-Length': end - start + 1,
    });
    fs.createReadStream(file, { start, end }).pipe(res);
  } else {
    res.writeHead(200, { 'Content-Type': mime, 'Accept-Ranges': 'bytes', 'Content-Length': total });
    fs.createReadStream(file).pipe(res);
  }
}
```

**改动 3：跨域 + Private Network Access（PNA）放行**

因为页面从阿里云公网打开，浏览器访问本地 `192.168.1.13:9123` 属于"公网页面 → 局域网资源"，Chrome 的 **Private Network Access** 策略会拦截。必须响应 CORS + PNA 头，并处理 OPTIONS 预检：

```js
function cors(res) {
  res.setHeader('Access-Control-Allow-Origin', '*');
  res.setHeader('Access-Control-Allow-Private-Network', 'true');   // 关键：PNA 预检放行
  res.setHeader('Access-Control-Allow-Headers', 'Range');
  res.setHeader('Access-Control-Expose-Headers', 'Accept-Ranges, Content-Length, Content-Range');
}
```

```js
const server = http.createServer((req, res) => {
  const url = new URL(req.url, `http://localhost:${PORT}`);
  cors(res);                                   // 所有响应统一带跨域头
  if (req.method === 'OPTIONS') {              // PNA 预检直接放行
    res.writeHead(204);
    res.end();
    return;
  }
  // ... 后续路由
});
```

启动方式：`npm run video-server`（=`node scripts/video-server.js`）。

### 3.2 前端源拼接 `src/lib/video-src.ts`

```ts
export async function getVideoBase(): Promise<string | null> {
  try {
    const res = await fetch('/api/video-server', { cache: 'no-store' });
    if (!res.ok) return null;
    const d = await res.json();
    return typeof d?.base === 'string' && d.base ? d.base : null;
  } catch {
    return null;
  }
}

export function withBase(src: string, base: string | null): string[] {
  const srcs: string[] = [];
  if (base && !/^https?:\/\//i.test(src)) {
    srcs.push(`${base}${src.startsWith('/') ? '' : '/'}${src}`);
  }
  srcs.push(src);
  return srcs;
}
```

### 3.5 云端媒体文件服务 `src/app/api/media/file/[name]/route.ts`

> ⚠️ 该路由用 `readFile` 一次性整读文件 + **不支持 Range**。大视频（几十 MB）从这里读会很卡。本地 9123 已支持 Range，因此**正常应走本地**，此路由只作兜底。

## 4. 过程中遇到的问题（按时间线）

### 问题 1：视频"一直读数据"放不出来
- **现象**：点视频一直转圈，放不了。
- **根因**：
  1. 云端 `/api/media/file/[name]` 用 `readFile` 整文件读入内存、无 Range 分段；
  2. 本地 9123 之前**不服务 `/api/media/file/` 路径**，前端拼出的本地地址 `http://192.168.1.13:9123/api/media/file/xxx.mp4` 返回 **404** → 自动回退云端 → 云端大文件慢/卡。
- **处理**：见 3.1 改动 1（9123 增加 `/api/media/file/` 映射 + Range）。

### 问题 2：切环节"点了没反应、要过一会儿"
- **现象**：教师端点下一个环节，很久才切换。
- **根因**：数据库在阿里云远程库 `8.130.70.114:5432`，`src/lib/classroom.ts:17` 注释明说"单次查询本身就要 ~28s"，`STATE_CACHE_TTL=30s` 就是为了扛这个慢查询。网络抖动时切环节就卡。
- **结论**：与视频无关，是远程库慢查询；建议看云数据库监控确认延迟。

### 问题 3：上传视频"一直显示上传中"
- **现象**：上传大视频，前端一直转"上传中"。
- **排查结果**：**文件实际已成功写入云端硬盘**（`/root/classroom-media/` 下可看到完整文件，MD5 与本地一致），接口实测正常（88MB 上传 13 秒返回 200）。是前端 `fetch` 等不到响应或用户没等完就切走。
- **教训**：上传完成后需点「插入」按钮才写入媒体库记录；不要在上传转圈时切页面。

### 问题 4（核心）：改成本地源后依然播放不了
- **现象**：媒体库 URL 填 `/api/media/file/a1-1.mp4`（本地有该文件），仍播放失败。
- **排查结果**：
  - 本地 9123 服务该文件正常：`HTTP 206 / 200`，且带 `Access-Control-Allow-Origin:*`、`Access-Control-Allow-Private-Network:true` ✅
  - **云端没有 `a1-1.mp4`**（`/root/classroom-media/` 下无此文件，`/api/media/file/a1-1.mp4` 返回 **404**）❌
  - 数据库媒体库记录存在：`slot=page:8de30503...`（A1 c9 视频页），url=`/api/media/file/a1-1.mp4`
- **结论**：浏览器从阿里云页面先请求本地 9123（本机能返回 206），**一旦本地源被浏览器 PNA/跨域拦截，就回退云端 → 云端 404 → 播放失败**。播放成败取决于"浏览器是否能成功访问本地 `192.168.1.13:9123`"。

## 6. 关键结论与正确用法

1. **文件必须放对地方**：要让视频走本地，视频文件必须存在于**本地笔记本** `public/media/`（或 `public/videos/`）。只在云端有、本地没有的文件，永远走云端。
2. **媒体库 URL 填相对路径**：填 `/api/media/file/<本地文件名>.mp4`，不要填 `http://` 开头的完整网址，也不要依赖「上传文件」按钮（上传=传到云端）。
3. **浏览器必须能访问本地 9123**：浏览器所在的机器要能访问 `http://192.168.1.13:9123`，且 9123 服务在运行。若浏览器不在笔记本局域网内，本地方案天然不成立。
4. **强刷**：改完配置或代码后，浏览器需强刷（Ctrl+Shift+R）清除旧缓存。
5. **验证方法**：
   - 视频**秒开** → 走本地 ✅
   - 有加载延迟 / 从公网拉取 → 走了云端
   - 浏览器直接访问 `http://192.168.1.13:9123/api/media/file/a1-1.mp4` 能播 = 本地链路 OK
