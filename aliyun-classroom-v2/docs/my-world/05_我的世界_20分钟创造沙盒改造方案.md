# 05《我的世界》20 分钟创造沙盒改造方案（工程决策版）

> 定位：`A3_WORLD` 试听课（小鸟课堂）**最后一个任务**，时长约 20 分钟。
> 目标：让学生**体验创造的快乐，以及"创造能带来价值"**——创造性被激发，就会得到一个很多人都想去用/去玩的产品。
> 本文是本次改造的**工程决策基线**，也是"后端大脑"方案的落地裁剪版。

---

## 0. 一句话锁定目标

> **20 分钟内：学生说一句话 → 东西立刻"活了" → 世界里的生命主动来用它 → 他看到数字涨、画面变、痕迹留下 → 他忍不住再改一次。**

学生在这 20 分钟里具体能做什么、能看到什么、什么反馈能刺激他继续做——**所有设计都必须围绕这个点**，而不是围绕"让世界模拟得更真实"。

---

## 1. 工程决策（先定架构，避免返工）

### 1.1 做"独立体验模块"，不推倒重来、不平滑侵入

- **不做**：新写一套平行世界引擎 / 把完整经济系统直接嵌进现有主引擎。
- **做**：在现有引擎上增加一个 `creation-sandbox` 模块，**用适配层复用现有**生命、位置、能量、关系和大屏渲染能力。
- 通过 feature flag / 独立路由 / 独立课程模式启动：

```ts
mode: "a3-creation-sandbox"
```

普通世界继续走旧逻辑，试听课进入新模式。这样 20 分钟体验可以大胆改，老师版和原有生命系统不会被第一版试验拖垮。

### 1.2 修正方案里的三个认知（后端大脑自己的纠偏）

1. **"五段运行卡"不是学生要填的流程。** 学生只说一句自然语言，系统**内部**解析成结构化作品；五段结构只用于引擎、调试、解释和回放，**不限制学生创作**。
2. **"六类创造"不是六套功能。** 生命/机器/场所/商品/活动/规则全部落到同一个运行模型 `触发条件 -> 执行动作 -> 产生结果 -> 影响世界`，类型只影响外观/默认动画/默认标签/默认事件/位置。
3. **第一波不优先做"六类"**，而是支持**一种通用可运行作品**，用标签和模板呈现出多种类型。真正决定 20 分钟是否有反馈的是四件事：

   1. 学生一句话能生成一个可运行作品；
   2. 世界能主动提供合适资源和体验者；
   3. 作品能在短时间内完成一次完整事件；
   4. 学生可以随时修改，并立即看到后果。

### 1.3 复用的现有能力（已核对代码）

| 现有文件 | 可复用什么 |
|---|---|
| `src/lib/world/traits.ts` | `chatWithLLM` + `ruleTraits` 的"文字→结构化"翻译模式（照搬到"一句话→Creation"） |
| `src/app/api/world/ai/route.ts` | `mode=create` 已实现"一句话→AI 生成 name/color/svg/text"，是新的 AI 解析器的现成范式；`sanitizeSvg` 可直接复用 |
| `src/lib/world/engine.ts` | `StateLife` 的状态/位置/关系/能量模型、`tick`/`advance` 惰性推进、`randPos` |
| `src/lib/world/store.ts` | JSON 原子读写范式（临时文件+rename） |
| `src/components/WorldScreen.tsx` | 大屏 Canvas 渲染入口、生命光点绘制 |
| `src/components/WorldStudent.tsx` | 学生端工作台、AI 对话、提交流程 |

## 2. 20 分钟内学生体验设计（做什么 / 看到什么 / 反馈如何刺激）

### 2.1 节奏设计（20 分钟闭环）

| 时间 | 阶段 | 学生做什么 | 学生看到什么 / 得到什么反馈 |
|---|---|---|---|
| 0–4 分 | 创造 | 对着一个大输入框说一句话："我想做一个把孤独变成音乐的机器" | 系统逐词"具象化"动画，生成一个作品 + 名字 + 外观 + 一张运行卡 |
| 4–10 分 | 验证 | 点"立即试运行"，或直接让它进共生缸 | 10 秒内看到自己的作品完整跑一遍；大屏上生命**带着原因**走过来使用它 |
| 10–16 分 | 升级 | 系统弹出"遇到的问题卡片"刺激升级；学生一句话改："让它需要两个人合作" | 世界立刻从单人变多人协作，出现明显新动画；新旧版本可同场对比 |
| 16–18 分 | 连接 | 系统提示"你的果汁机需要水果，小林的花园正在生产水果"，一键连接 | 两个作品连接后触发**第三种组合结果**，连锁事件发生 |
| 18–20 分 | 结算 | 大屏高光回放 | 自动回放"你的作品第一次被使用/第一次连接"片段 + 多维度标签 |

### 2.2 六类作品示例（第一版以"通用可运行作品 + 标签模板"呈现）

| 类型 | 学生可做的例子 | 第一次运行时看到什么 |
|---|---|---|
| 生命 | 会寻找孤独伙伴的发光鸟 | 它发现落单生命，飞过去陪伴并点亮周围 |
| 机器 | 把废料做成飞行玩具的机器 | 收集废料、加工、吐出玩具，生命拿走试飞 |
| 场所 | 只有两人合作才能开启的花园 | 两个生命到场，花园开放并长出新资源 |
| 商品 | 喝下后变色唱歌的果汁 | 生命选择口味，饮用后变色并触发音乐 |
| 活动 | 自动邀请害羞生命参加的舞会 | 舞台发出邀请，参与者聚集并出现集体动作 |
| 规则 | 每次帮助别人附近就长一朵花 | 帮助事件发生后，世界地面立刻开花 |

### 2.3 学生端改造清单（`WorldStudent.tsx`）

- 首页只保留：一个大输入框 + 语音输入 + 3 个灵感问题，**先不出现参数**。
- 生成后显示可点击的"运行卡"，任何一段（它是什么/何时启动/做什么/产出什么/谁想用）都能用自然语言重写。
- 增加"立即试运行"按钮，随时主动验证创意。
- 增加实时三段反馈："正在触发什么 / 现在做什么 / 世界发生什么变化"。
- 增加"谁在使用、为什么使用"列表，点击可定位到共生缸中的实际事件。
- 增加"遇到的问题卡片"（用真实运行结果刺激升级，不是 AI 泛泛建议）。
- 增加一句话升级 + 版本对比（修改保留其他设定，避免重新创建）。
- 增加"连接别人的作品"入口，只展示 2–3 个最匹配建议。
- 增加作品发布卡 + 高光回放（学生选最满意的瞬间）。
- 所有等待 >3 秒的生成都要持续展示作品正在形成，不能只有加载动画。

### 2.4 共生缸改造清单（`WorldScreen.tsx` + 引擎侧）

- 支持渲染四类新对象：**生命、固定设施、可拾取物品、局部区域/活动**。
- 每个作品运行时有**原因气泡**（"小觉需要能量，找到了你的月亮旅馆"）——这是最打动人的反馈。
- 增加**个人高光镜头**：某作品运行时，大屏短暂跟随放大，显示"触发→动作→结果"，再返回全局。
- 增加**事件导演**：全班作品多时轮流制造高光，不偏心最早/居中的。
- 增加**世界痕迹**：作品运行后留下开花/铺路/点亮/建桥，学生离开后仍可见。
- 不搞单一人气榜，改多种可同时成立的标签："连接最多 / 改变世界最大 / 最出乎意料 / 帮助最精准 / 升级变化最大"。

## 3. 共生缸后端第一波改造（复用现有引擎，新增 creation-sandbox 模块）

### 3.1 新增模块结构

```text
src/lib/world/
  engine.ts                      # 现有引擎（不改主逻辑）
  store.ts                       # 现有 JSON 存取（新增 creation 相关文件读写）
  creation/
    types.ts                     # Creation / Trigger / Action / Output / Effect 等类型
    parser.ts                    # 一句话 → Creation（AI + 规则回退，复用 traits 范式）
    runtime.ts                   # 执行 CreationRule：trigger→action→output→effect
    director.ts                  # 世界机会生成器 + 事件导演 + 资源兜底
    matcher.ts                   # 需求匹配（生命 needs ↔ 作品 tags）与作品连接
    trace.ts                     # 世界痕迹 / 高光回放记录
```

### 3.2 核心模型（最小结构，AI 只翻译不生成代码）

```ts
type Creation = {
  id: string
  creatorId: string
  kind: "life" | "machine" | "place" | "item" | "activity" | "rule"
  name: string
  description: string
  tags: string[]
  position: Point
  rules: CreationRule[]
  version: number
  status: "draft" | "active" | "paused"
}

type CreationRule = {
  trigger: Trigger
  action: Action
  outputs: Output[]
  effects: Effect[]
}
```

引擎**只执行 `CreationRule`**，不关心学生输入的是生命、机器人还是商店。

```ts
type Trigger =
  | { type: "resource_found"; tag: string }
  | { type: "life_nearby"; tags?: string[] }
  | { type: "need_present"; need: NeedType }
  | { type: "multiple_lives"; count: number }
  | { type: "time_elapsed"; seconds: number }
  | { type: "creation_connected"; creationId?: string }

type Action =
  | { type: "collect"; resourceTag: string }
  | { type: "transform"; inputs: string[]; output: string }
  | { type: "invite"; targetTags?: string[] }
  | { type: "help"; effect: Effect }
  | { type: "exchange"; output: string }
  | { type: "change_zone"; effect: Effect }
  | { type: "start_activity"; activityTag: string }

type Output = { id: string; name: string; tags: string[]; quantity: number; usableBy: "life" | "creation" | "zone" | "activity"; effects: Effect[] }

type Effect =
  | { type: "energy"; amount: number }
  | { type: "relationship"; amount: number }
  | { type: "appearance"; value: string }
  | { type: "movement"; value: string }
  | { type: "spawn_resource"; tag: string }
  | { type: "spawn_object"; tag: string }
  | { type: "zone_change"; value: string }
```

### 3.3 需求驱动的生命（体验者）

生命从"随机走动的背景角色"变成"有理由做事的体验者"：

```ts
type NeedType = "energy" | "company" | "play" | "curiosity" | "rest" | "safety" | "material" | "cooperation"
type Need = { type: NeedType; intensity: number; preferredTags: string[] }
```

简单匹配规则（第一版够用）：

```text
生命需要 energy    && 作品标签含 healing/food/drink   => 有概率前往
生命需要 company   && 作品标签含 social/music/companion => 有概率前往
生命需要 rest      && 作品标签含 quiet/safe/shelter     => 有概率前往
```

**关键**：大屏必须展示因果（"小觉现在能量不足，正在寻找你的月亮旅馆"），而不是只让学生看到角色随机靠近。

### 3.4 世界机会生成器（资源兜底 / 舞台调度）

最关键的**后端能力**。学生自由创造后，世界主动生成一个能让作品运行的机会，**保证 20 分钟内每个作品至少能成功运行一次**：

```ts
type WorldOpportunity = {
  creationId: string
  requiredTags: string[]
  requiredNeeds?: NeedType[]
  requiredActors?: number
  resourceSpawns: ResourceSpawn[]
  actorAssignments: ActorAssignment[]
  expiresAt: number
}
```

例：学生写"把垃圾做成玩具的机器" → 安排"附近出现废弃物；一两个生命搬运废弃物；至少一个生命对玩具感兴趣；机器有足够时间加工"。
例：学生写"需要两个人一起唱歌才能打开的门" → 安排"两个不同生命经过；都有可触发唱歌的行为；合理时间内同时到达；开门后出现新区域或物品"。

**兜底铁律**：每个作品至少保障——一份能触发它的资源 + 一个可以使用结果的生命 + 一次可以发生的事件。这不是作弊，是教学场景的舞台调度。

### 3.5 作品产物与自动连接

作品的输出**不能只是数字**，必须是世界中的对象或状态：

```ts
type CreationLink = {
  sourceCreationId: string
  outputTags: string[]
  targetCreationId: string
  inputTags: string[]
  active: boolean
}
```

连接成立后产生明显连锁事件：

```text
小林的花园生产水果 → 小周的果汁机加工水果 → 小王的舞台使用果汁做活动道具 → 生命参加"彩虹丰收节"
```

### 3.6 局部区域效果（学生改变环境，不只是角色数值）

```ts
type ZoneEffect = { zoneId: string; trigger: Trigger; effect: Effect; duration: number; radius: number }
```

例：学生写"只要有人在这里帮助别人，地面就开花" → 检测 help 事件 → 触发 zone effect → 生成花朵 → 留下世界痕迹。这类反馈极强，因为学生改变的是共生缸本身。

### 3.7 世界痕迹（我改变了一个共同世界）

```ts
type WorldTrace = { creationId: string; eventType: string; position: Point; visual: string; description: string; createdAt: number; persistent: boolean }
```

痕迹可以是：一条路 / 一座桥 / 一片花 / 一个发光区域 / 一种新资源 / 一栋小建筑 / 一个会继续运行的小装置。
必须可控：不删他人作品、不无限扩张、不永久锁死区域、不独占资源、数量范围有限。

### 3.8 事件导演

多个学生同时创作时，不能让所有事件同时发生。导演负责：发现即将触发的作品 → 安排资源和生命 → 提高相关区域可见度 → 放大关键事件 → 结束后恢复全局 → 轮流照顾不同学生。

```ts
type WorldEvent = { id: string; creationId: string; participants: string[]; phase: "trigger" | "action" | "output" | "impact"; priority: number; startedAt: number; duration: number }
```

导演**不是替学生播放预录动画**，它调用真实运行规则，只负责安排一个能让规则发生的环境。

### 3.9 三种运行来源

```ts
runMode: "natural" | "opportunity" | "preview"
```

| 模式 | 说明 |
|---|---|
| natural（自然运行） | 作品在正常世界中自己寻找资源/对象/机会，可产生意外 |
| opportunity（机会运行） | 世界导演按需求安排资源和参与者，保证 20 分钟内发生 |
| preview（强制预演） | 学生主动要求验证时，10 秒内搭建最小场景演示完整逻辑 |

三者结合：学生既看到确定反馈，又能继续观察不可预期的结果。

## 4. 后端"失败也产生有趣结果"（不让学生觉得答错）

自由创造不能要求每个想法一次成功。不实用也要有结果：

```text
成功运行 / 部分运行 / 产生意外结果 / 需要合作 / 暂时无人使用
```

反馈示例（不是"作品无效"）：

> "音乐成功产生了，但现在还没有人知道怎么使用它。你想让它吸引谁？"

---

## 5. 第一版不做（避免复杂度吞噬 20 分钟）

- 真实货币、商品定价、复杂库存、供需价格变化、完整市场；
- 永久破坏、复杂政治或社会阶层；
- 每个生命独立的长周期记忆；
- 任意规则代码生成（AI 只组合受支持规则，不生成代码）；
- 所有作品都能互相组合；
- 复杂的经济平衡。

---

## 6. 底层保护规则（对教学不可见）

```text
任何创造都不能永久删除其他学生的作品
任何作品都不能独占全部资源
任何效果都有最大范围和持续时间
每个作品都拥有最低限度的试运行资源
同一作品不能无限刷取影响
世界始终保留新资源和新机会
```

---

## 7. 最终工程目标（一句话）

> **给共生缸增加一个"创造承接层"：任何学生创意进入世界后，系统能够为它提供适合的资源、参与者和运行机会；作品运行后产生具体产物、生命反应、局部环境变化和可持续痕迹；产物还可以被其他生命或作品继续使用。**

第一版真正要跑通的链路：

```text
学生创造
  -> 引擎解析成规则
  -> 世界提供机会
  -> 作品执行动作
  -> 产生具体结果
  -> 生命或其他作品使用
  -> 环境留下痕迹
  -> 作品进入下一次创造
```

只要这条链路真实跑通，学生无论创造生命、机器、商店、花园还是游戏，都能在共生缸里看到自己的想法发生作用。

---

## 8. 实施优先级建议

**第一波（让 20 分钟爽起来的最低闭环，先做）：**
1. 一句话 → 生成可运行作品（`parser.ts`，复用 `world/ai` 范式）
2. 世界机会生成器（`director.ts`，资源兜底 + 保证一次成功）
3. 需求驱动的体验者（`matcher.ts`，原因气泡）
4. 一键试运行（`preview` 模式）

**第二波（加强爽感）：**
5. 作品自动连接 + 组合结果
6. 高光回放 + 事件导演
7. 版本对比 / 一句话升级

**接入方式：** 通过 `mode: "a3-creation-sandbox"` 独立开启，普通世界不受影响。
