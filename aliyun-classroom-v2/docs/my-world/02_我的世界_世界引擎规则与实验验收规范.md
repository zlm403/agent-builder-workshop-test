# 《我的世界》世界引擎规则与实验验收规范

> 文档版本：V1.1
> 内部编号：A3（模块 `A3_WORLD`）
> 配置版本建议：`my-world-engine-spec-v1.1`
> 目标系统：`aliyun-classroom-v2`（Next.js + Prisma + PostgreSQL）
> 本文档是世界机制、关系反馈、埋点和实验验收的主规范。

---

## 1. 目的

世界引擎必须证明以下闭环真实存在：

```text
生命根据规则做出行为
↓
行为改变能量、资源、关系、位置或状态
↓
变化进入下一次决策
↓
生命和世界产生可测量的新结果
```

其中最关键的问题是：

> 生命之间形成的关系，是否会反过来改变后续行为和世界结果？

必须严格区分：

1. 系统记录了关系；
2. 关系实际参与决策；
3. 关系改变了互动概率；
4. 关系形成了稳定群体；
5. 群体进一步改变资源、能量或存活结果。

不能只根据画面、关系连线或关系数量判断社会结构已经形成。

---

## 2. 引擎运行架构

世界引擎作为**独立 TS 后台进程**运行（Node/tsx），连同一 PostgreSQL。参考现有 `water-analyzer.py` 的"独立后台进程"模式，但技术栈用本项目一致的 Node/TypeScript。

建议数据流：

```text
PostgreSQL
（WorldLife / WorldRun / WorldEvent / 课堂控制状态）
↓
world-engine 独立进程（tsx scripts/world-engine.ts 运行）
↓
消费学生提交和教师控制指令
↓
推进固定时间步模拟
↓
原子写回 PostgreSQL
↓
Next.js API route 只读状态（按角色裁剪）
↓
教师端、大屏端、学生端轮询 / SSE
```

引擎必须支持：

- 启动；
- 停止；
- 暂停；
- 继续；
- 固定时间步；
- 加速或无头运行（A/B 实验用）；
- 随机种子；
- 状态恢复；
- 单实例锁（避免两个引擎进程同时写同一世界）；
- 事件消费偏移量；
- 原子状态写入；
- 引擎版本记录；
- 配置版本记录。

**不得**把持续模拟循环放入 Next.js route handler 的请求处理函数。

V1 不强制引入 WebSocket。三端实时沿用 `realtime.ts` + SSE；世界状态可加短轮询兜底。

## 3. 引擎模式与版本隔离

引擎允许存在不同运行配置，但数据不得混用。

### 3.1 实验模式

实验模式用于 A/B 关系反馈实验。

必须保持：

- 固定 10 个生命原型；
- 固定初始能量；
- 固定死亡阈值；
- 固定资源和事件参数；
- 固定移动速度；
- 固定能力代价；
- 每次运行 600 模拟秒；
- 只改变关系是否参与决策。

实验模式沿用当前基线语义：

```text
energy <= 0
→ 生命死亡
→ 记录 deathCause 和 deathTime
```

在完成 A/B 实验前，不得把死亡改成可恢复休眠，否则 B 组历史基线失去可比性。

### 3.2 课堂模式

课堂模式可在后续产品版本中将失活表现为"休眠"，以避免学生过早失去参与感。

但是：

- 课堂模式必须使用独立配置版本；
- 休眠是否可恢复必须明确；
- 不得与实验模式数据合并；
- 不得用课堂模式结果替代 A/B 实验；
- 任何恢复规则都必须重新测试能量平衡；
- V1 第一阶段可以先沿用实验模式行为，只在学生文案中使用中性"失活"表达。

| L02 | 帮助者 |
| L03 | 连接者 |
| L04 | 照亮者 |

## 5. 固定时间步与随机数

引擎必须使用固定模拟时间步，避免设备性能改变结果。

每次运行记录：

```text
seed
fixedDeltaSeconds
durationSimSeconds
engineVersion
configVersion
relationshipFeedbackEnabled
```

A、B 组应尽量共享：

- 初始位置；
- 初始能量；
- 生命参数；
- 资源生成随机流；
- 世界事件随机流；
- 公共事件随机流。

关系反馈导致生命路径发生变化后，后续碰撞不同属于实验结果，不应强行保持一致。

禁止使用未记录来源的全局随机数。

## 7. 资源系统

资源统计必须区分：

```text
资源对象产生数量
资源能量单位产生数量
资源对象获取数量
资源能量单位获取数量
```

对应世界级指标：

```text
totalResourcesProduced
totalResourceUnitsProduced
totalResourcesCollected
totalResourceUnitsCollected
```

必须避免把"资源对象个数"和"资源能量单位"混为一谈。

资源规则包括：

- 在允许区域按配置产生；
- 具有稳定 ID；
- 记录产生时间和位置；
- 记录能量单位；
- 被获取后移除或减少；
- 记录获取生命；
- 记录获取前后能量；
- 资源未被获取时记录消失原因。

实验期间不得为了提高存活率临时增加资源。

## 9. 生命决策

每次决策至少读取：

```text

当前状态

附近危险
附近生命
与附近生命的关系
能力状态
区域偏好
当前世界事件
冷却时间
```

决策过程建议分为：

```text
感知
↓
生成候选行为
↓
计算基础倾向
↓
应用紧急生存约束
↓
应用性格影响
↓
按实验组决定是否应用关系影响
↓
应用能力和冷却限制
↓
选择行为
↓
执行行为
↓
记录原因和结果
```

每次关键行为必须记录：

```text
action
targetId
reasonCode
reasonData
result
energyDelta
resourceDelta
relationshipDelta
positionDelta
```

不得由 AI 或前端在事后猜测原因。

## 10. 生命相遇与真实互动

两个生命进入相遇范围时记录一次相遇。

"相遇"和"真实互动"必须分开：

```text
相遇：两个生命进入规定空间范围
真实互动：执行了帮助、分享、连接、竞争、攻击等改变状态的行为
```

普通靠近、穿过或无行为接触不能自动算作真实互动。

每一对生命必须逐对记录：

```text
encounterCount
realInteractionCount
helpCount
shareCount
connectionCount
competitionCount
attackCount
avoidCount
firstEncounterTime
lastEncounterTime
relationshipMin
relationshipMax
relationshipDuration
```

还必须按关系阶段拆分：

```text
陌生阶段
弱关系阶段
强关系阶段
负向关系阶段
```

每个阶段分别记录：

```text
相遇次数
互动次数
帮助次数
分享次数
攻击次数
回避次数
再次相遇次数
```

任一阶段互动率不得因统计错位超过 100%。

## 11. 关系系统

关系值建议范围：

```text
-100 至 +100
```

默认阶段：

```text
-100 至 -30：负向关系
-29 至 9：陌生或疏离
10 至 29：熟悉
30 至 59：连接
60 至 100：强关系
```

关系可以因以下行为变化：

```text
帮助
分享
连接
合作
攻击
竞争
伤害
回报
长时间未接触
```

所有关系变化必须记录：

```text
生命对
变化前关系
变化量
变化后关系
触发行为
模拟时间
```

关系衰减必须由配置控制，不能在 A、B 组间不同。

## 12. A 组关系反馈规则

### 12.1 总体原则

A 组设置：

```text
relationshipFeedbackEnabled = true
```

关系数据参与后续决策。

关系影响至少覆盖两个以上独立行为渠道，V1 目标覆盖：

```text
靠近或远离
帮助或分享
攻击或回避
再次相遇
短时群体移动
```

### 12.2 关系影响靠近和远离

正向关系可以：

- 提高将对方作为移动目标的倾向；
- 提高在无紧急生存目标时再次靠近的概率；
- 提高短时间保持邻近的倾向。

负向关系可以：

- 提高回避倾向；
- 降低主动靠近倾向；
- 在谨慎型生命中提高逃离优先级；
- 在攻击型生命中提高防备或反击倾向。

关系不能覆盖以下高优先级条件：

- 即将死亡；
- 严重危险；
- 能力不可用；
- 目标超出感知范围；
- 冷却时间未结束。

### 12.3 关系影响帮助和分享

正向关系可以提高：

```text
帮助概率
分享概率
回报帮助概率
目标优先级
```

但帮助必须同时满足：

```text
帮助者拥有足够能量
目标确实可以获得收益
能力未冷却
帮助成本可支付
```

不得让生命因关系强而无条件帮助到死亡。

是否需要保留最低自保能量阈值，必须通过配置表达，并在 A、B 组保持相同；只有"关系加权是否生效"不同。

### 12.4 关系影响攻击和回避

负向关系可以：

```text
提高回避概率
提高防备概率
在允许攻击的原型中提高攻击倾向
降低分享与帮助倾向
```

关系不能把原本没有攻击能力的生命变成攻击型生命。

### 12.5 关系影响群体移动

满足配置条件的强关系生命可以形成短时群体：

- 至少达到稳定群体要求的最小成员数；
- 成员间存在足够数量的强关系边；
- 群体持续时间达到阈值；
- 群体内部互动率高于外部；
- 群体移动不能永久锁定；
- 资源、危险和能量仍可使成员离开。

### 12.6 关系影响必须有上限

关系反馈必须采用有界加权，不得无限放大。

实现时应使用配置化上限，例如：

```text
maxApproachModifier
maxAvoidModifier
maxHelpModifier
maxAttackModifier
maxTargetPriorityModifier
```

具体数值应记录在配置版本中。

在第一次完整 A/B 实验完成前，不得根据单次结果反复调大关系权重来追求显著差异。

## 13. B 组关系记录规则

B 组设置：

```text
relationshipFeedbackEnabled = false
```

B 组允许：

- 记录关系；
- 更新关系值；
- 统计关系阶段；
- 统计帮助、分享、连接、竞争、攻击和回避；
- 统计关系持续时间；
- 在实验结束后分析网络。

B 组禁止：

- 决策读取关系值；
- 因关系强而靠近；
- 因关系弱而回避；
- 因被帮助而提高回报概率；
- 因被攻击而提高后续攻击或逃避概率；
- 根据关系形成群体移动；
- 使用关系值改变目标优先级。

关闭反馈时，所有关系加权必须完全旁路，而不是把权重近似设为零。

## 14. 能力与代价

每个生命 V1 最多拥有一个核心能力。

建议能力类型：

| 能力 | 效果 | 代价 |
|---|---|---|
| 恢复 | 为目标恢复能量 | 自身消耗能量 |
| 照亮 | 显示隐藏资源 | 降低速度或消耗能量 |
| 连接 | 促进关系建立 | 暂停移动或消耗能量 |
| 探测 | 提前发现资源或危险 | 持续消耗能量 |
| 防护 | 降低危险影响 | 降低资源获取能力 |

每个能力必须包含：

```text
触发条件
作用对象
效果
代价
冷却时间
使用限制
失败条件
```

能力代价必须真实扣除。

特别检查：

- 治疗或恢复能力不能只增加受助者能量而漏扣施助者代价；
- 帮助者能量不足时不得透支使用能力；
- 受助收益必须记录实际增加值，不能使用估算文案；
- 分享、连接和帮助必须分别计数。

## 15. 世界平衡

世界可监控：

```text
世界总能量
平均生命能量
资源密度
事件密度
活跃生命数
死亡或失活数
互动数量
帮助和攻击比例
生命聚集程度
```

实验模式中，任何自动平衡逻辑必须：

- 在 A、B 组完全一致；
- 使用同一配置；
- 记录触发时间和调整结果；
- 不读取实验组标签；
- 不为 A 组或 B 组单独补偿。

在完成关系反馈实验前，不得因为帮助者早死而单独调整：

```text
危险伤害
资源数量
初始能量
帮助成本
移动消耗
死亡阈值
```

先完成 A 组实现并运行完整对照，再讨论参数问题。

## 19. 稳定小群体判定

不能把最大连通分量大于零直接当作稳定群体。

稳定群体必须同时满足配置化条件：

- 成员数达到最小值；
- 群体内部存在足够强关系边；
- 持续时间达到阈值；
- 群体内部互动率高于群体外；
- 成员在多个时间窗口中保持；
- 不是一次事件造成的瞬时聚集。

每个识别出的群体必须输出：

```text
groupId
成员生命ID
形成时间
结束时间
持续时间
内部强关系边
内部互动率
外部互动率
形成触发事件
解散原因
```

没有符合条件的群体时必须写：

```text
无稳定群体
```

不得显示为数值 `0` 并让读者误认为统计缺失。

```text
稳定小群体

```

## 21. A/B 实验安排

固定实验矩阵：

| 实验组 | Seed 101 | Seed 202 | Seed 303 |
|---|---:|---:|---:|
| A 组：关系反馈开启 | 600秒 | 600秒 | 600秒 |
| B 组：关系反馈关闭 | 600秒 | 600秒 | 600秒 |

总计 6 次运行。

实验要求：

- 固定 10 个生命原型；
- 每个原型只生成 1 个；
- A、B 组使用相同随机种子；
- 使用同一出生位置表；
- 使用相同初始能量；
- 使用相同资源和事件参数；
- 使用相同能力和代价；
- 只改变 `relationshipFeedbackEnabled`；
- 使用同一引擎版本；
- 使用同一配置版本；
- 所有数据来自引擎埋点；
- 允许无头或加速运行；
- 不允许画面目测补数据。

## 22. 自动判定规则

### 22.1 生态运行成立

满足：

- 资源持续产生；
- 事件持续产生；
- 至少 50% 的生命在运行中存活过；
- 世界不是前几十秒全部死亡。

### 22.2 生命互动成立

满足：

- 总相遇次数大于 0；
- 实际互动次数大于 0；
- 至少 3 个不同生命参与互动。

### 22.3 关系网络成立

满足：

- 至少 3 对关系达到强关系阈值；
- 至少有关系持续 60 秒以上。

### 22.4 关系反馈成立

以下至少满足两项：

- 强关系互动率高于陌生阶段；
- 强关系再次相遇率高于陌生关系；
- 强关系帮助率高于陌生阶段；
- 群体内部互动率高于群体外部；
- 强关系生命存活率高于无强关系生命；
- 关系建立后能量或资源结果发生稳定变化。

这些差异必须结合 A/B 组判断，不能仅凭 A 组内部相关性证明因果。

### 22.5 社会结构初步成立

必须同时满足：

- 关系反馈成立；
- 至少出现一个符合规则的稳定群体；
- A 组相较 B 组至少两个世界级指标稳定变化；
- 变化在 3 个种子中方向基本一致。

## 23. 最终结论

最终结论只能使用以下四种之一：

```text
A. 尚未形成可测量的社会结构
B. 已形成生命互动和关系网络
C. 已观察到关系反馈和稳定小群体
D. 已观察到关系驱动的社会涌现
```

每个结论必须列出支持它的具体指标。

不能只输出"形成社会"或"没有形成社会"。

如果只完成 B 组，或 A 组尚未运行，应使用保守结论，并明确：

```text
关系反馈对照尚未完成，不能判断关系是否改变行为。
```
