## 3. 历史基线中的测量能力

历史引擎增加或确认了以下埋点，原则上只补测量，不改变原有行为逻辑：

### 3.1 死亡归因

记录：

```text
deathCause
deathTime
```

死亡原因至少区分：

```text
danger
attack
exhaustion
```

### 3.2 能量流向

能量收入和损失按来源拆分：

```text
资源收入
他者帮助或分享收入
移动消耗
能力消耗
危险损失
攻击损失
```

### 3.3 行为分类

分别统计：

```text
帮助
分享
连接
攻击
相遇
真实互动
```

### 3.4 资源统计口径

区分：

```text
资源对象数量
资源能量单位
```

避免"获取资源数大于产生资源数"等口径混淆。

### 3.5 关系逐对统计

每一对生命记录：

```text
相遇次数
真实互动次数
行为类型

关系最大值
关系持续时间
陌生阶段统计
弱关系阶段统计
强关系阶段统计
```

## 9. 埋点和数据异常修复记录（历史）

历史运行和报告校验发现并修复了以下问题，新引擎实现时应避免复发：

### 9.1 事件触发字段名不一致

曾同时出现：

```text
totalEventTriggers
totalEventsTriggered
```

这会造成：

```text
undefined++
→ NaN
→ 报告显示"—"
```

统一字段为：

```text
totalEventTriggers
```

引擎累加点、结果映射和报告输出必须全部使用同一名称。

### 9.2 关系阶段统计错位

曾出现弱关系阶段互动率大于 100% 的异常。

该问题来自阶段聚合错位，不是实际行为结果。

阶段统计已经修正，必须保证：

```text
某阶段真实互动次数 <= 该阶段相遇次数
```

### 9.3 生命 ID 跨运行不固定

实验生命 ID 必须强制固定为：

```text
L01 至 L10
```

不得让运行时生成 ID 影响跨种子比较。

### 9.4 群体空结果表达不准确

无符合条件的稳定群体时，应输出：

```text
无稳定群体
```

不得只输出数字 `0`。

### 9.5 受助能量文案使用近似值

帮助产生的受助收益必须使用真实埋点值。

不得根据帮助次数估算能量收益。

### 9.6 帮助显著性文案不准确

帮助次数为 0 或样本不足时，不得使用：

```text
帮助次数显著高于平均
```

### 9.7 最终能量显示为负零

报告输出应把：

```text
-0
```

规范化为：

```text
0
```
