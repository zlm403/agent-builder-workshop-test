# 06 · 行为语言与综合解释器契约（《我的世界》A3 · Behavior v1）

> **本文是什么**：让学生创意生命真正"会行动"的完整设计基准——现状调查结论 + 字段契约 + 综合解释器/校验器规格 + 验收样例 + 下一阶段边界。后续所有实现（prompt、validator、决策核）以本文为准。

## 〇、总架构原则（先读这个，防止以后方向摇摆）

**Behavior 不是生命的"属性"，而是生命的"行为程序"。**

```
旧（第一代 tags+attrs）：
生命
 ├─ tags = cautious / curious / social / stubborn   ← 四选一人格标签
 └─ attrs = 七维数值                                 ← 只管代价与观感
       ↓
   if / else if 链
       ↓
    行为

新（Behavior v1）：
学生六块创意
       ↓
综合行为解释器（AI）
       ↓
Behavior v1
 ├─ seek   我更愿意靠近什么
 ├─ rules  遇到什么事情，我先怎么做（有序）
 └─ body   我反应得多快、多远、多久
       ↓
大屏行为决策核（规则解释器）
       ↓
    行动
       ↓
现有物理世界（粒子 / SVG / 浪潮 / 关系 / 能量 —— 全部复用，零改动）
```

**两句铁律：**

1. **标签只是解释结果，Behavior 才是生命的行动逻辑。** 人格标签（如"怕生但热心肠"）只能从已提取的行为中归纳出来用于展示，永远不参与决策——这从根本上消灭了第一代"四选一压扁人格"的问题：标签不再是输入，而是输出。
2. **Validator 可以拒绝 AI 的输出，但不能替 AI 补行为。** AI 没输出 `friendHurt→help`，Validator 不许因为"这个生命看起来很善良"就自动补一条。门卫不是编剧。

## 一、为什么要做 Behavior

### 1.1 学生生命为什么是白板粒子

学生生命进入大屏的唯一通道是 `bigscreen.html` 的 `spawnStudentLife()`（L2093），它调 `makeCustomLife()`（L2064，同名函数的第二份定义，JS 提升 rules 后者覆盖前者），而它：

- **不传 `tags`** → `tags = opts.tags || []` → **空数组**；
- **不传 `attrs`** → 七维一律 50（总和 350 ≠ 公平池 100，控制台一直在警告）。

于是所有学生生命出生即同模板白板：感知半径全员 300（150×(1+50/100×2)）、能耗相同、性格分支全不命中（`decidePersonality` 四个标签全 miss → 落入默认"随机改变方向"；`lifeWaveReact` 全 miss → 只会缓缓减速）。

学生唯一能生效的输入是表现层：`skill[块].visuals`（含 AI 生成的自包含 SVG 动画）在事件瞬间播放。**所以学生会看到"我的生命会在相遇时放出我说的动画，但它平时活得跟别人的生命一模一样"。**

### 1.2 老师生命为什么有趣

`LIFE_DEFS`（L195–208）里六个示例生命（小蓝/小红/小绿/小黄/小紫/小青）每个都被**手工赋予**了不同的 tags 和七维属性：小蓝谨慎会逃、小红好奇围观、小黄社交拉伴、浪潮来了谨慎者逃/好奇者着迷/社交者聚拢。趣味来自这套硬编码差异，而不是任何通用机制。

### 1.3 第一代语言的三个结构性缺陷

1. **决策词汇量只有 4 个词**，且 if-else 链按第一个命中生效——双标签组合是假的（小紫 `['cautious','social']` 在决策层永远只表现为 cautious，她的 social 标签是死重）。连老师的复合人格都被压扁。
2. **连续参数层与选择层脱节**：七维 attrs 只调节代价（受伤/恢复/能耗/视野/观感），没有一个参与"往哪走、帮不帮、躲不躲"的选择判断。就算把学生描述完美翻译成七个数字，性格也不会变。
3. **装饰性第二层证明词表早就不够用**：`custom:{calm/wonder/tenacity/warmth/guard/spark}`（L197–207）注释声称"可被反应/规则读取"，实际全文件零消费，只在 tooltip 展示。老师当年想表达更多，没找到挂载点，只留在了名片上。

## 二、现有引擎调查结论（2026-08-26 实测，含行号）

### 2.1 双引擎事实与现役链路（重要背景）

| 链路 | 组成 | 现状 |

## 三、Behavior v1 设计原则（六条）

1. **解释，不创造**：Behavior 是 AI 对学生已表达的生命观念的解释结果。学生没表达的行为不存在——哪怕再"合理"也不补。宁可少解释，不要替学生创造。`rules: []` 完全合法且预期常见。
2. **原话 > 结构**（B > A）：学生原话是唯一事实来源；第一轮六块提取的 skillText 只是辅助（仅当该块原话为空时参考）。冲突时信原话——不能让一个 AI 的误读覆盖学生自己的表达。
3. **顺序就是优先级**：规则从上到下第一条命中生效。规则的排列顺序由综合理解决定，是人格的核心组成部分，任何环节不得重排。
4. **封闭词表**：when × do 只能在 §5 词表内取值，出词表即丢弃，不许猜近义词替代。
5. **标签 display-only**：label 只能概括已输出的 rules/params，永不进引擎。
6. **失败退白板**：LLM 失败/超时/坏 JSON → BLANK 兜底，绝不阻塞提交（与 ruleSpec 兜底哲学同源：AI 失败不 502 不黑屏）。

## 四、Behavior v1 字段契约

```js
{
  v: 1,
  label: "",                       // ≤12字人格描述，display-only
  seek: {                          // 目标偏好权重（目标选择加权用）
    people:    <number 0–2, 默认1>,   // 生命
    resources: <number 0–2, 默认1>,   // 资源
    events:    <number 0–2, 默认1>    // 事件/新东西
  },
  rules: [                         // 有序条件反应表，≤4 条，顺序=优先级
    { when: <§5 词表>, do: <§5 词表> }   // 注意：v1 无 strength 字段（已删除，
  ],                                   // 强度差异由顺序+body+seek 吸收）
  body: {                          // 身体/情绪参数
    senseRadius:        <0.5–2,  默认1.0>,   // 感知半径倍率
    personalSpace:      <10–150, 默认60>,    // 个人空间 px（密度容忍）
    speedMul:           <0.5–2,  默认1.0>,   // 移动速率倍率
    dwellSec:           <0–15,   默认2>,     // 观察驻留秒数
    temperSec:          <0–20,   默认0>,     // 被激后情绪持续秒数
    reactionDelaySec:   <0–5,    默认0>      // 反应延迟秒数（慢性子）
  }
}
```

总量 ≈17 个数据位。每一个都能指认来自哪个人格样例（见 §10），没有一个是凭空设计的。

## 五、when / do 封闭词表

### when（刺激条件，7 个）

| 词 | 含义 |
|---|---|
| `dangerNear` | 附近出现危险（倒霉事件/浪潮威胁） |
| `hitBy` | 自己被撞/受击 |
| `strangerNear` | 没有建立过关系的生命靠近 |
| `friendHurt` | 建立过关系的伙伴受伤/能量低 |
| `friendThreatened` | 危险逼近自己的伙伴 |
| `newThingNear` | 出现新的事件或新东西 |
| `crowded` | 周围生命太多太挤 |

### do（反应动作，7 个）

| 词 | 含义 |
|---|---|
| `flee` | 快速逃离现场 |
| `retreat` | 慢慢后退拉开距离（不离开视野） |
| `observe` | 凑近并停留观察一段时间 |
| `approach` | 朝目标靠近 |
| `help` | 跑过去帮助（**带位移**，区别于现有原地输能） |
| `confront` | 迎向刺激源（反击/护友共用此动词） |
| `gather` | 向同伴聚集 |

**v1 边界说明**：资源不出现在 when 词表里（贪吃靠 seek.resources 权重表达；护食者的 otherNearMyResource 记入 §11 缓期）。friendNear 若最终无独立消费者可在实现时砍成 6 词。

## 六、综合解释器输入契约

```js
// POST /api/a3/behavior 请求体
{
  convos:    {创造,交流,反应,资源,潮流,成长},   // B：学生六块原话，可为空串
  skillText: {                                // A：仅文字字段
    创造:{name,blurb}, 交流:{approach,avoid,onMeet},
    反应:{manifest,dropDims}, 资源:{consume},
    潮流:{mode}, 成长:{grow,death}
  }
}
```

- **显式排除**：visuals/SVG 数组、sketch 图片、hue/name 外观、dims 账本——它们不是行为的证据，喂进去只会诱导 AI 从表演反推性格。
- **优先级**：B 为准，A 仅在该块 B 为空时参考；冲突信 B。
- **运行位置**：客户端在提交前调用 `/api/a3/behavior`（沿用 llm.ts 服务端代理模式），拿到 behavior 一并 POST 到 `/api/a3/world/life`。不让 LLM 阻塞存储路径。
- ⚠️ **传输前提（实现必改）**：当前 `POST /api/a3/world/life` 只存 skill，六块原话从未上传。提交载荷必须新增 `convos` 随行落库（调试可见性：老师能翻原话对质"它为什么老躲人"）。
- **时点与幂等**：提交时刻一次性生成，随 life 记录落库；学生改描述重新提交才重算。`v:1` 版本号留迁移门。

## 七、Prompt 规格（POST /api/a3/behavior）

调用参数：`temperature: 0.2`、`json: true`、`maxTokens: 500`、`timeoutMs: 15000`。

System Prompt 分五段（实现时逐段写入）：

1. **角色**："你是数字生命的行为解读员。学生已用六段话描述了他创造的生命。你不是设计师，没有创造权——你的唯一任务是：从他已经说出的话里，辨认出这个生命会怎么行动，翻译成固定格式。他没说过的行为，不存在。宁可少解释，不可替他创造。"
2. **证据优先级**："原话（convos）是唯一事实来源；skillText 只是辅助，仅当某块原话为空时参考该块；两者冲突信原话。摘要里字段存在 ≠ 行为被表达过。"
3. **两张词表**（§5 原样写入，含每个词的一句含义）。
4. **保守解读协议**：每条规则必须能在原话找到对应句子，找不到就不输出；强度拿不准取最轻档（flee/retreat 拿不准→retreat；approach/observe 拿不准→observe）；规则顺序=学生表达的先后；程度词→参数映射表（senseRadius"看得远"→1.4–1.8 / personalSpace"怕生"→80–120、"爱热闹"→20–30 / speedMul"跑得快"→1.2–1.4、"慢性子"→0.7–0.85 / dwellSec"看很久"→6–10 / temperSec"气消得慢"→8–15 / reactionDelaySec"慢半拍"→1.5–2.5；seek"总想着吃"→resources:2 等）；禁止事项复述（不从长相/表现推行为、不做跨生命假设、不输出词表外词汇、不确定就不输出、只输出 JSON）。
5. **输出格式**（§四 JSON 模板原样）+ label 约束："只能概括你已输出的 rules 和参数，是读出来的印象不是写进去的设定；规则为空时只能中性描述（如'安静的小家伙'）。"

响应：成功 `{ok:true, behavior}`；任何失败 `{ok:false}` → 客户端落 BLANK。

## 八、Validator 规格（纯函数，门卫，非编剧）

位置：`src/lib/world/behavior.ts` 导出 `validateBehavior(raw)`；服务端在 `POST /api/a3/world/life` 存储前单点执行。

处理顺序（逐步写死）：

| 步 | 规则 |
|---|---|
| 1 | raw 非对象 → 整体返回 BLANK |
| 2 | `raw.v !== 1` → 整体返回 BLANK（不猜未知版本） |
| 3 | seek 三键：Number()；NaN/undefined→1；clamp [0,2] |
| 4 | rules：非数组→[]；逐条 when∉白名单 或 do∉白名单或缺字段/类型错 → **丢弃并记入 dropped**；通过后截断保序取前 4；不去重、不合并、**永不重排** |
| 5 | body 六键：Number()；NaN→默认；clamp 区间（§四所列） |
| 6 | label：非字符串→''；字符串截断 ≤20 字 |
| 7 | 返回 `{behavior, dropped}`；dropped 随记录落库（老师可查"哪条被门卫拦了"） |
| 8 | 任何输入不得 throw——最坏结果就是 BLANK |

白名单常量与 §5 逐字一致。**Validator 只验证和裁剪，不排序、不补全、不建议**——一旦它开始"逻辑上应该这样排"，它就成了第二个编剧。

## 九、BLANK 兜底（全链路唯一失败形态）

```js
{ v:1, label:'',
  seek:{people:1,resources:1,events:1},
  rules:[],
  body:{senseRadius:1,personalSpace:60,speedMul:1,dwellSec:2,temperSec:0,reactionDelaySec:0} }
```

触发场景：LLM 失败/超时/坏 JSON/v 不匹配/raw 非对象。效果 = 白板粒子行为 + 学生自己的表现动画（与今天的现状一致，优雅降级）。

## 十、八个生命验收样例（盲眼程序测试 8/8 通过，2026-08-26）

以下八份 JSON 是契约的验收基准：交给一个不知道学生原话的程序，仅凭 JSON 必须能重现右侧旁观者印象。

```js
// 1. 害羞但热心（帮友必须排在怕生前——顺序即优先级）
{seek:{people:.3,resources:1,events:.5},
 rules:[{when:'friendHurt',do:'help'},{when:'strangerNear',do:'retreat'}],
 body:{senseRadius:1,personalSpace:80,speedMul:1,dwellSec:1,temperSec:0,reactionDelaySec:0}}

// 2. 什么都好奇（dwellSec=8 就是"看很久才走"）
{seek:{people:1,resources:1,events:2}, rules:[{when:'newThingNear',do:'observe'}],
 body:{senseRadius:1.3,personalSpace:40,speedMul:1,dwellSec:8,temperSec:0,reactionDelaySec:0}}

// 3. 脾气暴躁（temperSec=10 承载"气消得慢"）
{seek:{people:1,resources:1.5,events:.5}, rules:[{when:'hitBy',do:'confront'}],
 body:{senseRadius:1,personalSpace:50,speedMul:1.1,dwellSec:1,temperSec:10,reactionDelaySec:0}}

// 4. 喜欢交朋友（全靠权重，零特殊机制）
{seek:{people:2,resources:.8,events:.5}, rules:[{when:'crowded',do:'gather'}],
 body:{senseRadius:1.1,personalSpace:30,speedMul:1,dwellSec:2,temperSec:0,reactionDelaySec:0}}

// 5. 喜欢独处（大 personalSpace + 无 gather 规则 = 不理邀约）
{seek:{people:0,resources:1,events:.5},
 rules:[{when:'crowded',do:'retreat'},{when:'friendHurt',do:'help'}],
 body:{senseRadius:.9,personalSpace:110,speedMul:.9,dwellSec:1,temperSec:0,reactionDelaySec:0}}

// 6. 贪吃（空规则表本身就是人格：什么都不怕，只认吃）
{seek:{people:0,resources:2,events:0}, rules:[],
 body:{senseRadius:1.4,personalSpace:20,speedMul:1.3,dwellSec:0,temperSec:0,reactionDelaySec:0}}

// 7. 胆小但聪明（看得远 1.8 + 起步早，跑得不快 0.9）
{seek:{people:.5,resources:1,events:.3}, rules:[{when:'dangerNear',do:'flee'}],
 body:{senseRadius:1.8,personalSpace:90,speedMul:.9,dwellSec:1,temperSec:0,reactionDelaySec:0}}

// 8. 保护者（confront 冲向威胁源=天然挡在中间；自己被撞反而退让）
{seek:{people:1.2,resources:.8,events:.5},
 rules:[{when:'friendThreatened',do:'confront'},{when:'hitBy',do:'retreat'}],
 body:{senseRadius:1.2,personalSpace:60,speedMul:1.2,dwellSec:1,temperSec:0,reactionDelaySec:0}}
```

## 十二、下一阶段：大屏行为决策核（本阶段边界声明）

> **本阶段只完成"学生创意 → 合法 Behavior"的翻译层。**
> **下一阶段要解决：Behavior → 世界中的实际行动。**

即：把 `bigscreen.html` 里 `lifeAI`(L1358) / `decidePersonality`(L769) / `lifeWaveReact`(L832) 三处同构的 if-else 决策链，重写成**一个统一的规则解释器**（每帧构建刺激快照 → 从上到下第一条命中规则生效 → 全不命中走默认游荡），并把写死的常量提升为 body 参数插槽。

### 12.1 已裁定的语义（直接带入决策核规格，不再讨论）

| 语义 | 裁定内容 |
|---|---|
| `retreat` ≠ `flee` | retreat=低速拉开距离、不离开视野（#1/#5/#8 用）；flee=高速逃离现场（#7 用）。混用会让害羞者像被吓飞 |
| `temperSec` 机制 | 被 hitBy 激怒后的 N 秒内，strangerNear 自动套用激怒它的那条规则的 do（否则"谁靠近都凶"演不出来） |
| `confront` 目标 | 快速逼近**刺激源**。#3 的源是撞它的事件，#8 的源是威胁朋友的危险——同一动词，保护行为自然涌现 |
| 新动词成本 | 只有"两个半"：help 带位移、confront、observe 加计时器；其余复用现有机制 |

### 12.2 待拷打开口问题（决策核盲眼程序测试第二轮的靶子）

1. `friendThreatened` 判定需要"看见伙伴周围的危险"——perceive 目前只扫自身周边；要不要扫伙伴周边？半径多大？
2. `friendHurt` 的"朋友"定义——relationships 目前仅在 bd<40 相遇时建立；陌生判定（strangerNear）用"无关系记录"还是关系阈值？
3. `help` 带位移的目标选取：多个低能量朋友帮谁？（建议：最近者优先，复用现有评分思路）
4. `observe` 的驻留计时器放哪（life 上加 dwellUntil？期间被打断怎么算？）
5. `reactionDelaySec` 的语义坑：延迟期间刺激继续逼近/消失怎么办？（锁存首个刺激还是重置计时？必须写死一种）
6. `crowded`/personalSpace 的精确判定式（几个生命、多大半径算挤？）
7. seek 权重如何进入目标选择：加权评分替换"找最近实体"的具体公式（距离归一化方式）
8. 规则评估频率与刺激快照的统一构建（三处 if-else 合一后的每帧流程）

### 12.3 方法

下一阶段照搬本次方法论：**先拿 7×7 词表逐格问"落到现有三个函数上是否有歧义"→ 盲眼程序测试 → 刁钻人格回归（§10 八条 + §11 六条反例）→ 冻结《07_大屏行为决策核规格》→ 最后一次性实现**。仍然先规格后代码，不边改边猜。
