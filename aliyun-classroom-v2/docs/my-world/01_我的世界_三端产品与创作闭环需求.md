# 《我的世界》三端产品与创作闭环需求

> 文档版本：V1.1
> 内部环节编号：A3（模块 `A3_WORLD`，接在 A2 快速入门网站之后）
> 学生端和大屏端显示名称：《我的世界》
> 目标系统：`aliyun-classroom-v2`（Next.js 14 + Prisma + PostgreSQL，试听课三端）
> 本文档是产品体验、三端职责和课堂流程的主规范。世界引擎规则见 `02_我的世界_世界引擎规则与实验验收规范.md`。

---

## 1. 产品定义

《我的世界》不是一个由学生直接操纵角色的游戏，而是一个由教师、学生和公共大屏共同参与的数字社会世界。

每位学生通过学生端创造一个数字生命。生命发布到公共世界后，由世界引擎根据学生设计的规则自主运行。

生命可以：

- 移动和探索；
- 获取资源；
- 消耗和恢复能量；
- 遇到世界事件；
- 与其他生命相遇；
- 帮助、分享、连接、竞争、攻击或回避；
- 建立正向或负向关系；
- 因已有关系改变后续行为；
- 在一定条件下形成稳定小群体；
- 在下一轮应用学生修改后的新规则。

本产品的核心不是"制作一个角色"，而是让学生体验：

> 我提出了一个想法，把它变成了生命规则；生命进入共同世界后，世界真的回应了我的创造。

---

## 2. 核心创作闭环

完整创作流程必须形成以下闭环：

```text
产生一个想法
↓
创造一个生命
↓
提交生命
↓
教师统一发布
↓
生命进入公共世界
↓
自主运行并与世界互动
↓
学生观察真实结果
↓
学生发现意外或问题
↓
学生查看行为原因并与AI讨论
↓
学生修改一条或多条规则
↓
提交生命新版本
↓
教师在下一轮统一应用
↓
比较修改前后的变化
↓
产生新的想法
```

V1是否完成，不以页面数量为标准，而以这个闭环能否真实运行作为第一验收标准。

## 3. 全局显示铁律

### 3.1 内部编号

以下位置允许出现"A3"或模块名 `A3_WORLD`：

- 教师端；
- 文件名；
- 代码模块名；
- 配置文件；
- 内部日志；
- 管理接口；
- 测试和实验报告。

以下位置不得出现"A3""环节3"或内部课程编号：

- 学生端；
- 公共大屏；
- 学生可见AI回答；
- 学生可见事件动态；
- 学生可见加载和错误页面。

学生端和大屏端统一显示：

```text
《我的世界》
```

### 3.2 课堂中不生成代码

教师点击"下一页"时，只激活预先实现好的场景和功能。

课堂现场不得：

- 临时生成前端代码；
- 动态修改世界引擎源码；
- 临时创建新的学生页面；
- 将未经验证的AI生成代码直接投入运行。

## 4. 三端职责

## 4.1 教师端

教师端负责控制课堂阶段和公共世界，不直接替学生创造生命。

教师可以：

- 进入《我的世界》课程（模块 `A3_WORLD`）；
- 准备世界引擎；
- 开始生命创造阶段；
- 查看学生连接数、草稿数和提交数；
- 截止本轮提交；
- 批量发布已提交生命；
- 开始、暂停、继续和结束世界；
- 切换观察阶段；
- 在大屏聚焦某个生命；
- 触发规范允许的预设公共事件；
- 开始修改阶段；
- 查看学生新版本提交进度；
- 在下一轮统一应用新版本；
- 展示修改前后的比较结果。

教师不能：

- 替学生修改生命规则；
- 直接控制某个生命的移动；
- 临时给特定生命增加资源或能量；
- 指定某个生命必须帮助或攻击另一个生命；
- 在实验运行期间修改平衡参数；
- 将学生尚未提交的草稿发布到世界；
- 让新版本在当前轮中即时覆盖运行版本。

---

## 4.2 大屏端

大屏端负责展示所有人共享的公共世界。

大屏的主要内容是持续运行的世界，而不是后台表格。

大屏显示：

- 世界区域；
- 所有已发布生命；
- 生命位置、移动和状态；
- 资源；
- 世界事件和公共事件；
- 生命之间的关键互动；
- 关系阶段变化；
- 群体形成和解散；
- 当前课堂阶段；
- 当前运行轮次；
- 被教师聚焦的生命；
- 经过筛选的关键事件动态。

大屏不显示：

- 学生完整编辑表单；
- 学生AI对话全文；
- 其他学生的完整生命规则；
- 教师管理按钮；
- 内部调试日志；
- 内部课程编号"A3"；
- 每一帧位置变化。

---

## 4.3 学生端

学生端是学生的个人创造、观察和修改工作台。

学生可以：

- 接收当前课堂任务；
- 创建自己的生命；
- 设置名称、外观和颜色；
- 设置性格倾向；
- 设置移动和互动倾向；
- 选择一个核心能力；
- 设置能力触发条件；
- 查看能力效果和代价；
- 提交生命；
- 查看自己生命的状态；
- 查看关键行为和行为原因；
- 查看与自己生命有关的重要关系；
- 与AI讨论真实运行结果；
- 创建生命新版本；
- 提交下一轮版本；
- 比较修改前后的结果。

学生不能：

- 直接操纵生命移动；
- 拖动生命在大屏中的位置；
- 操作其他学生的生命；
- 查看其他学生的完整规则；
- 任意修改能量和资源；
- 绕过能力代价；
- 在当前轮即时替换正在运行的版本；
- 让AI未经确认直接提交规则。

## 5. 现有系统接入方式（aliyun-classroom-v2 真实机制）

> 本节依据 `aliyun-classroom-v2` 现有代码编写，是硬约束。

### 5.1 模块接入

《我的世界》作为新模块 `A3_WORLD` 加入课程模板 `src/lib/courseConfig.ts` 的 `TEMPLATE.modules`，**位置在 `A2_SITE` 之后、`A08_WRAP` 之前**（A2 最后一步"最后升华"本就指向"进入 A3"）。

需要新增的模块配置（仿照现有 `A2_SITE` 的写法）：

```ts
{
  id: 'A3_WORLD',
  type: 'world',           // 新 ModuleType（需在 src/lib/types.ts 补充）
  title: '我的世界',
  durationSeconds: 1800,
  teacherContent: { /* 教师端控制面板描述 */ },
  studentTask: {},
  screenContent: { phase: 'world' },
}
```

`ModuleType` 联合类型需追加 `'world'`；`src/lib/pages.ts` 的 `PAGE_GROUPS` 追加 `'A3'`，`BUILTIN_SEEDS` 追加 A3 内置页（见 5.4）。

### 5.2 三端页面切换（复用现有机制，不新建推送协议）

现有系统**没有**"教师向学生推送路由页面"的独立机制。三端切换完全依靠：

```text
currentModuleId + moduleSubState（存 ClassSession）
→ classroom.ts 控制函数（advance/jump/setModuleSubState）
→ realtime.ts publish → SSE（/api/events/[sessionId]）
→ 教师端/大屏/学生端各自按 moduleId+subState 渲染
```

《我的世界》必须复用这条链路：

- 教师端：`AvatarTeacher` 扩展支持 A3 环节的页序列控制（点页= `setSubState`）；
- 大屏端：`(screen)/screen/page.tsx` 增加 `module.type === 'world'` 分支，渲染 `WorldScreen`；
- 学生端：`(student)/student/page.tsx` 增加 `current.type === 'world'` 分支，渲染 `WorldStudent`。

子状态建议命名（subState）：

```text
world:hook       世界预告（大屏） / 等待（学生）
world:create     创建生命（学生表单）
world:submit     提交截止
world:publish    批量发布（教师）→ 生命进入世界
world:run        世界运行中（大屏完整世界 / 学生观察自己的生命）
world:observe    观察讨论（聚焦生命与事件）
world:revise     修改新版本
world:apply      统一应用 V2
world:compare    前后比较
```

### 5.3 数据存储（Prisma 表，不建第二套事件流）

现有系统用 Prisma 直连 PostgreSQL，**没有** `events.jsonl` 或 `POST /api/collect`。学生提交直接写各环节业务表（如 `A2SiteEntry`）。

《我的世界》需要新增 Prisma 模型：

```text
WorldLife       每名学生的生命（含版本 V1/V2 草稿与当前版本、规则 JSON、提交状态）
WorldRun        一场世界运行（sessionId、roundId、开始/结束、种子、配置版本、A/B 组标记）
WorldEvent      关键事件日志（发布/互动/关系变化/资源获取/休眠/恢复/公共事件）
```

关系反馈实验如需隔离，可新增 `WorldExperimentRun`（记录 group=A/B、seed、运行参数、结论），**不得与课堂数据混用**。

### 5.4 环节页面序列

`src/lib/pages.ts` 的 `BUILTIN_SEEDS` 追加 A3 内置页，复用现有"PPT 式页序列"能力（大屏按 subState 逐页渲染、教师端点页投屏、内置页可隐藏不可删）：

```text
{ group: 'A3', moduleId: 'A3_WORLD', refKey: 'world:hook',     label: '世界预告' },
{ group: 'A3', moduleId: 'A3_WORLD', refKey: 'world:create',   label: '创建生命' },
{ group: 'A3', moduleId: 'A3_WORLD', refKey: 'world:submit',   label: '提交截止' },
{ group: 'A3', moduleId: 'A3_WORLD', refKey: 'world:publish',  label: '发布生命' },
{ group: 'A3', moduleId: 'A3_WORLD', refKey: 'world:run',      label: '世界运行' },
{ group: 'A3', moduleId: 'A3_WORLD', refKey: 'world:observe',  label: '观察讨论' },
{ group: 'A3', moduleId: 'A3_WORLD', refKey: 'world:revise',   label: '修改新版本' },
{ group: 'A3', moduleId: 'A3_WORLD', refKey: 'world:apply',    label: '应用新版本' },
{ group: 'A3', moduleId: 'A3_WORLD', refKey: 'world:compare',  label: '前后比较' },
```

`groupOfModule` / `builtinLabel` / `defaultModuleOf` 需同步支持 `A3`。

### 5.5 世界引擎

世界模拟必须独立于浏览器和学生连接。学生关闭页面或断网后，生命必须继续运行。

V1 采用**独立 TS 后台进程** `world-engine`（参考 `water-analyzer.py` 的后台进程模式，但用 Node/TS 连同一 PostgreSQL）：

```text
PostgreSQL（WorldLife / WorldRun / WorldEvent）
↓
world-engine 独立进程（tsx 运行，固定时间步推进）
↓
读课堂控制状态（A3_WORLD 的 subState / 教师指令）
↓
推进模拟：移动、能量、资源、事件、互动、关系、A/B 反馈开关
↓
写回 PostgreSQL（原子）
↓
Next.js API route 只读状态 → 教师端/大屏/学生端轮询（或 SSE）
```

**不得**把持续模拟循环放进 Next.js 的 route handler 请求处理逻辑。

V1 不强制引入 WebSocket。三端用现有 `realtime.ts` + SSE，世界状态可加一层短轮询兜底。

### 5.6 AI 讨论

AI 复用现有 `src/lib/llm.ts` 的 `chatWithLLM`（含 DeepSeek key 配置、重试、离线 mock 回退）：

- 把学生想法转换成候选规则；
- 解释真实运行结果（必须基于该学生生命真实数据）；
- 帮助学生提出下一轮假设；
- 比较修改前后差异。

约束：

- API 密钥不发送到学生端（key 只存服务器 `.env.local` / 教师端设置）；
- AI 不可用时用规则模板完成基础解释（复用 `llm.ts` 的 mock 回退）；
- AI 不能自动提交规则；学生必须确认修改；
- AI 不得访问其他学生的完整私人规则。

## 6. 课堂状态机

课堂状态统一包括（映射到 `moduleSubState`，存 `ClassSession`）：

```text
world:hook
world:create
world:submit
world:publish
world:run
world:observe
world:revise
world:apply
world:compare
```

| 状态 | 教师端 | 大屏端 | 学生端 | 世界是否推进 |
|---|---|---|---|---|
| world:hook | 检查引擎和连接 | 显示《我的世界》准备中 | 显示《我的世界》准备中 | 否 |
| world:create | 查看创造进度 | 显示等待加入和提交数量 | 创建或编辑生命 | 否 |
| world:submit | 截止、检查提交 | 显示等待发布 | 确认已提交或继续等待 | 否 |
| world:publish | 批量发布生命 | 显示生命进入世界 | 显示发布结果 | 否 |
| world:run | 暂停、继续、聚焦 | 完整公共世界 | 查看自己的生命 | 是 |
| world:observe | 选择案例和事件 | 聚焦生命、关系或事件 | 查看原因、关系和日志 | 可配置 |
| world:revise | 查看修改进度 | 显示本轮结果 | 创建新版本 | 按教师设置 |
| world:apply | 统一应用新版本 | 显示生命版本更新 | 等待下一轮 | 否 |
| world:compare | 选择比较内容 | 展示前后变化 | 查看个人比较 | 否 |

状态切换必须由教师端现有课程控制链路发起（`control('setSubState', ...)`），并由服务端保存。

前端刷新后必须能恢复当前状态（`currentModuleId + moduleSubState` 已在 DB，不依赖浏览器内存）。

## 7. 学生创造生命

## 7.1 创建步骤

学生创建生命采用分步流程：

```text
第1步：它是谁
第2步：它喜欢怎样行动
第3步：它有什么能力
第4步：它愿意付出什么代价
第5步：确认并提交
```

每个生命至少包括：

```text
生命名称
外观
主颜色
性格倾向
移动偏好
互动偏好
一个核心能力
能力触发条件
能力代价
一句话创作想法
```

V1最多允许一个核心能力，避免规则组合失控。

## 7.2 生命版本

生命必须使用版本机制：

```text
当前运行版本：V1
学生修改草稿：V2 Draft
学生提交：V2 Submitted
教师统一应用：V2 Active
```

约束：

- 当前运行版本不可被即时覆盖；
- 学生只能修改自己的生命；
- 新版本在下一轮统一生效；
- 每次应用必须记录版本号和应用时间；
- 比较功能必须能关联应用前后的两个版本；
- 被退回或未提交的草稿不得进入世界。

## 8. 大屏画面

大屏布局采用：

```text
左侧世界状态
+
中央公共世界
+
右侧关键动态
```

中央世界必须占据主要面积。

### 8.1 左侧世界状态

显示：

- 当前轮次；
- 世界运行时间；
- 已发布生命数；
- 活跃生命数；
- 失活或休眠生命数；
- 世界平均能量；
- 当前资源状态；
- 当前公共事件；
- 当前课堂阶段。

不显示复杂后台参数和调试数据。

### 8.2 中央公共世界

显示：

- 生命；
- 资源；
- 世界区域；
- 世界事件；
- 公共事件；
- 关键互动；
- 有限且可理解的关系效果；
- 稳定群体的视觉提示。

普通关系连线不得全部常亮。只有聚焦、强关系变化或群体说明时才显示必要连接，避免画面变成关系网图。

### 8.3 右侧关键动态

优先显示：

- 新生命进入；
- 获取关键资源；
- 帮助、分享或连接；
- 竞争、攻击或回避；
- 关系阶段变化；
- 进入失活或恢复；
- 公共事件开始或结束；
- 稳定群体形成或解散；
- 新版本开始运行。

不显示每一帧移动和微小能量变化。

## 9. 学生观察页面

"我的生命"至少显示：

- 名称和外观；
- 当前版本；
- 当前能量；
- 当前状态；
- 当前行为；
- 行为原因；
- 最近关键事件；
- 重要关系；
- 本轮资源和能量变化；
- 查看比较；
- 与AI讨论；
- 修改下一版本。

行为原因必须来自引擎记录的 `reasonCode` 及其数据，不得由前端或AI事后猜测。

示例：

```json
{
  "action": "help",
  "reasonCode": "FRIEND_LOW_ENERGY_SELF_SAFE",
  "reasonData": {
    "selfEnergy": 67,
    "targetEnergy": 24,
    "relationshipStrength": 71
  }
}
```

## 10. AI 讨论

AI 只承担以下职责：

1. 把学生想法转换成候选规则；
2. 根据真实运行数据解释行为结果；
3. 帮助学生提出下一轮假设；
4. 比较规则修改前后的差异。

约束（见 5.6）：密钥不下发、AI 失败规则回退、必须引用真实数据、数据不足必须明说、不能编造原因、不能自动提交、学生必须确认。

---

## 11. 状态接口与数据权限

浏览器不得直接连 PostgreSQL。`server.py` 的概念不适用——本系统由 Next.js API route 提供只读状态接口。

按角色裁剪的接口要求：

- 大屏读取公共可视状态；
- 学生只读取自己的完整生命数据及必要公共信息；
- 教师读取课堂控制和统计数据；
- 其他学生完整规则不得发送到学生端；
- 不得只依赖前端隐藏敏感字段；
- 服务端必须在响应前裁剪数据。

## 12. V1 范围

V1 必须完成：

- `A3_WORLD` 模块接入课程模板（A2 之后）；
- 三端 subState 页面序列（A3 组内置页）；
- 教师激活《我的世界》；
- 学生创建和提交生命；
- 教师查看提交进度；
- 教师批量发布；
- 后台世界引擎持续运行；
- 生命自主移动；
- 能量、资源和事件；
- 生命相遇和真实互动；
- 关系形成并影响后续行为（A 组关系反馈）；
- 学生查看行为原因；
- 学生与AI讨论；
- 学生提交新版本；
- 教师统一应用新版本；
- 前后比较；
- 大屏左右信息和中央世界；
- 断线恢复（世界引擎独立运行）；
- 按角色裁剪状态数据。

V1 暂不实现：

- 学生摇杆控制；
- 排行榜；
- 多种货币；
- 学生实时聊天；
- 开放式代码执行；

- 强制引入 WebSocket；
- 无限种AI能力；
- 无限制实时修改生命；
- 完整学术级社会网络分析界面。

## 13. 产品验收流程

必须无需临时改代码即可演示：

1. 教师进入内部 `A3_WORLD`；
2. 大屏显示《我的世界》准备状态；
3. 教师开始创造（`world:create`）；
4. 学生工作台切换到创建生命 pane；
5. 学生创建并提交生命；
6. 教师看到提交进度；
7. 教师批量发布生命；
8. 生命进入大屏公共世界；
9. 世界引擎持续推进；
10. 生命移动、获取资源并受到事件影响；
11. 至少两个生命发生真实互动；
12. 互动改变能量、资源或关系；
13. 关系在后续决策中被实际读取；
14. 大屏显示关键事件；
15. 学生查看自己的行为及原因；
16. 学生与AI讨论真实结果；
17. 学生创建并提交V2；
18. 当前轮仍继续使用V1；
19. 教师在下一轮统一应用V2；
20. 学生和大屏看到前后变化；
21. 学生断线重连后状态可恢复；
22. 其他学生的完整规则没有泄露。

验收时不得：

- 手工修改数据库或状态文件；
- 临时修改源码；
- 用前端动画假装世界引擎已运行；
- 用AI编造生命行为原因；
- 把"记录了关系"当成"关系改变了行为"。
