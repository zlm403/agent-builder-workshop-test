# 上机视频本地化与换机迁移（笔记本视频源优先 · 云端回退）

> 对应代码功能：**教室笔记本视频源优先，阿里云公网兜底**（2026-08-20 落地，commit 见交接记录）。
> 相关：`scripts/video-server.js`（笔记本本地服务）、`src/app/api/video-server/route.ts`（地址配置 API）、教师端「视频服务器地址」输入框、`src/lib/video-src.ts` + `src/components/SmartVideo.tsx`（前端统一读取）。

---

## 一、理念（为什么要做）

课程视频（2 个 mp4，共约 113MB）目前存在阿里云公网 `/api/media/file/`，学生在大屏/内容页播放时走公网，教室网络差时会卡、灰屏。

上机电脑（上课笔记本）网络好、离大屏近——把视频源指向**笔记本电脑的本地服务**，局域网内播放又快又稳；笔记本没开机/地址没配时**自动回退公网**，什么都不影响。

**优先级**：`笔记本 http://IP:9123/videos/xxx.mp4` → 本机 `/videos/xxx.mp4` → 云端 `/api/media/file/xxx.mp4`。
浏览器按 `<source>` 顺序自动向后回退，前端代码无感。

## 二、教师端怎么填地址

1. 打开教师端 → 右上角工具条出现「**视频服务器地址**」输入框。
2. 填笔记本本地服务的基址，形如 `http://192.168.1.20:9123`（**笔记本开的脚本会打印所有本机 IP**）。
3. 点「保存」→ 显示「已保存 ✓」。**即时全局生效**（学生端/大屏端下一次加载视频自动走新地址），无需重新构建/刷新后端。
4. 地址存服务器文件 `data/video-server.txt`；**留空点保存 = 清空配置，回退公网**。

> 可填 `http://IP:9123` 或 `http://IP:9123/videos`（系统自动去掉末尾 `/` 和 `/videos` 后缀归一化）。

## 三、笔记本跑脚本（上课第一步）

笔记本与老师机在同一局域网，在**上机笔记本**上：

```bash
# 项目已拷贝到笔记本后（含 public/videos/）：
cd aliyun-classroom-v2
npm run video-server
# 等价于 node scripts/video-server.js（纯 Node，无任何依赖，装过 Node 就能跑）
```

启动后打印类似：

```
教室笔记本视频服务已启动
端口：9123
视频目录：<项目>/public/videos
教室局域网学生电脑访问用这个 IP:9123：
  http://192.168.1.20:9123
```

浏览器打开 `http://localhost:9123/` 可见文件名列表（验证服务正常）。支持 Range 请求，拖动进度条不卡。

## 四、要拷哪些文件到笔记本

| 内容 | 位置 | 说明 |
|---|---|---|
| 视频文件（2 个 mp4，约 113MB） | **`public/videos/` 整个目录** | 当前：`a1-reality.mp4`、`1786677398421-7ncl82.mp4` |
| 视频服务脚本 | `scripts/video-server.js` | 纯 Node，拷整个仓库或只拷「脚本 + public/videos/」都行（脚本用 `__dirname` 定位，放哪都能跑） |

> 换机/备份提示：视频文件大、不易每次重新下载，建议上机电脑固定一台专门跑视频服务。

## 五、换机迁移步骤（换一台电脑当视频源）

1. **拷文件**：把 `public/videos/` 整个目录（2 个 mp4）拷到新上机电脑的项目里，保证路径 `public/videos/xxx.mp4`。
2. **起服务**：新电脑 `node scripts/video-server.js`，看打印的本机 IP。
3. **改地址**：教师端「视频服务器地址」填成 `http://<新电脑IP>:9123` → 保存。
4. **验证**：学生端/大屏打开视频页面，确认能播、拖动进度条不卡；或直接浏览器访问 `http://<新电脑IP>:9123/videos/a1-reality.mp4`。

## 六、回退说明（不填地址就是公网）

- **不填 / 清空地址** → 视频走原公网链路 `/videos/` → `/api/media/file/`，行为与改造前一致。
- **笔记本没开机 / IP 填错 / 不在同一网段** → 前端请求笔记本源失败，浏览器自动回退下一条源，**会稍有延迟但能出画面**（第一帧前有一次失败请求）。

## 七、FAQ（灰屏 / 卡顿排查）

| 现象 | 排查 |
|---|---|
| 视频灰屏打不开 | ① 笔记本 `npm run video-server` 在跑吗？ ② 地址填对了吗（含端口）？ ③ 学生电脑能 ping 通笔记本 IP 吗（同一局域网）？ ④ 浏览器直接开 `http://<IP>:9123/` 看能不能出列表 |
| 播放卡顿/加载慢 | 优先查**笔记本到学生端/大屏的无线网络**；笔记本建议插网线；信号弱时大屏可能仍走公网（回退），属预期 |
| 拖动进度条卡住 | 老视频 moov 在文件尾部会拖不动（如 `a1-reality.mp4` 重编码前版本）。**视频服务器已支持 Range**，正常可拖动；若仍卡，用 `ffmpeg -i in.mp4 -movflags +faststart out.mp4` 重编码后再替换 |
| 保存地址报错 | 地址必须以 `http://` 或 `https://` 开头；格式 `http://IP:9123` |
| 学生端看到的还是公网 | 教师端保存后，学生端/大屏**重新加载页面**（或刷新视频块）才拉新配置；真机确认后让浏览器刷新 |
